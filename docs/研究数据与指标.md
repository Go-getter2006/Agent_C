代码位置写在每一条后面；导出都在教师端“日志申请”，带学号和姓名，按学号和期末考试系统的成绩对（自己对）。

## 2. 指标定义

每个数都能从导出的记录复算。定义改了就改版本号，导出文件的 `request.versions` 里带着，分析时按版本分段。

### 卡点（`app/stuckstats.py`，版本 `stuck-kp-1`）

一次卡点：学生在求助回合里卡在某个技能上，智能体记下一条。原始记录是技能一层，页面按知识点汇总、展开看技能。

| 指标 | 分子 / 分母 |
|---|---|
| 卡住 | 这个知识点上有卡点的学生数 · 卡点条数 |
| 反复 | 在这个知识点上卡住过两个及以上回合的学生数 |
| 顽固 | 第三次及以上卡在同一个技能上的学生数 |
| 第二次自己想起来 | 第二次卡在同一技能、智能体先请他回忆时自己说出来的次数 / 第二次卡住且已经有结果的次数 |
| 卡后通过 | 卡住时绑定了题、这道题之后在 XDOJ 上通过的次数 / 卡住时绑定了题的次数 |
| 之后新题一次通过 | 第一次卡在这个知识点以后才开始做的、主知识点是它的题（不含卡住的那几道），第一次提交就通过的题数 / 这样的题数 |
| 没来问 | 这个班布置的、主知识点是它的题上，通过前（或到现在）没通过的提交不少于 3 次、却没就这道题开过求助回合的学生数。还在评测的提交不算 |

“之后新题一次通过”要和对照组比才有意义：导出的提交记录里有每道题第一次提交的结果，可以算同一批学生卡住之前、或没卡住的同学在同一知识点上的比例。

### 老师盲评（`app/rating.py`，版本 `rating-1`）

- 材料和大模型看到的一样（`assess.dialogue`：已知情况和最后 16 条对话，去掉学号姓名），不显示学生是谁、大模型和规则的等级、摘抄的原话。
- 每位老师的顺序按（老师, 评估编号）的哈希打乱，每次打开都一样，评过的不再出。“看不出来”单独记，不进一致率。
- 一致率：完全一致、相差不超过一档、Cohen's κ、二次加权 κ（差两档比差一档扣得多，等级有先后时用这个）。四档固定为 0～3，不按出现的类别算。
- 下调的效果：大模型原始等级被约束下调过的那些里，下调后离老师更近、一样、更远各几个。
- 两位老师之间：同一条有两位老师评过的，取最先评的两位。这是人和人能到的一致程度，大模型和老师的一致率要和它比。

### 判断、定位、修改（`app/diagnosis.py`，版本 `dims-1`）

见 [创新点与方法](创新点与方法.md) 5.5 节和 `diagnosis.py` 开头。定位、修改只算独立作答（`protocol` 2），旧版记录不补。

分析学生的代码诊断表现时，按知识点汇总首次判断正确率、实际选行后的首次定位命中率，以及未看提示和未运行样例就提交的首稿通过率。每项同时报告分子、分母和进入该步骤的人数。分析间隔保持时，使用同一知识点的新题表现与实测间隔。半衰期模型的保持值、求助推断的独立性和提交过程算出的改错分可用作选题依据或预测变量。

### 图模型（`graph-2026-11-19b`）

后验使用 v2 的作答证据，计入已标注的提交失败和通过可信度。先验只取先修技能的平均掌握，多个先修节点的影响有统一上限。有至少两次尚无改正证据的已标注失败时，才列出有直接证据且估计偏低的先修技能供复查。多人共有的线索按独立学生去重。

图模型通过 `guess + (1 - slip - guess) × 掌握后验` 估计首次通过概率。旧预测保留原版本和数值。分析时以预测日志的 `model_version` 分组。

模型检验可切换预测版本。当前版本展示近六周，历史版本从该版最后一次预测所在的周向前取六周。当前版本没有样本时默认显示最近有记录的历史版本。每次只比较同一版本、同一批首次提交记录。旧版 `2026-11-17a` 的图模型列记录的是掌握估计，其 Brier 只用于历史查看。多维融合和消融仍单独使用同一批有这两项数值的记录。

“反复失败的技能”展示至少两次尚无改正证据的同技能失败。能指出先修技能时加上复查线索，依然缺少具体先修证据时保留原失败记录。

### 导出的字段

- 小题、复习：`protocol`、`itemVersion`、`judgedHasBug`、`judgeCorrect`、`firstLines`、`locateHit`、`firstFixPass`、`firstFixClean`、`hints`、`sampleRuns`、`events`（记录备题、实际查看、首次判断、首次定位、修改等事件）、`durationMs`、`skipped`。首稿代码不导出。
  有明确作业提交来源的新作答还会导出 `triggerAt`（提交时间）、`triggerReason`、`phase`（近期检查 recent 或间隔复习 delayed）。首次确认判断时记录 `secondsSinceTrigger`。分析近期与延迟表现应使用这个实测间隔。只有备题或打开过题目的学生还没有首次判断数据。没有历史时间依据的旧记录留空。
- 复习排序 `evidence-priority-1` 先满足至少一天的间隔。到期后主要看已有作答显示的薄弱程度、反复错误与修改、需要确认独立性的通过。单纯经过较长时间只影响到期时间和同一优先级内的顺序。新生成的复习题记录 `phase=delayed`，以前的 `recent` 记录保留。
- 掌握模型 `2026-11-19b` 保留同一题同技能的递减失败证据。改对后，单次失败保留原权重的 20%，反复失败保留 55%。疑似雷同仍按 40% 计入正向通过证据，不作为独立做对或新增失败。
- 求助回合：`maxHelp`、`helpCount`、`askedBack`、`failedReplies`、`located`、`studentMessages`、`minutes`、`endReason`、`bound`。
- 卡点：`kp`、`skill`、`nth`、`resolution`、`stubborn`、`passed`、`triesAfter`、`passedAt`、`round`。
- 理解评估：`basis`、`level`、`rawLevel`、`ruleLevel`、`source`、`confidence`、`adjusted`、`evidenceCount`、`promptVersion`、`human`（每位老师的等级和用时）。勾了“包括原文”才有摘抄的原话。

## 3. 学期里要做的

1. **开学前定版本，学期中不改**：提示词（`config.PROMPT_VERSION`）、各指标的版本。非改不可时记下日期，分析时分段。
2. **盲评**：每周评 20～30 个回合，一学期攒到 100 个以上（κ 的置信区间才不会太宽）。请第二位老师评其中至少 50 个，算老师之间的一致率。
3. **期末导一次全量**：JSON，全部类别，时间段覆盖整个学期。每行有学号，拿学号和期末考试系统的成绩对上。文件里有学号、姓名，按学校的要求保管；论文里出现的表格只用汇总的数，或者自己把学号换成编号。
4. **原文**：只在要做质性分析时勾。学生的话里可能有认得出人的内容，引用之前人工看一遍。
5. **告知和同意**：按学校要求告诉学生会收集哪些记录、怎么用。

## 4. 局限

- “没来问”的阈值 3 次是定的，不是学出来的；导出里有原始提交，可以换阈值重算。
- “卡后通过”“之后新题一次通过”是描述性的：卡住以后得到的帮助、题目本身的难度、学生自己的努力混在一起，不能直接读成帮助的效果。
- 盲评的老师可能就是这门课的任课老师，认得出学生的说话方式；材料里不给名字只能减轻、不能消除。
- 演示数据是编的，上面算出来的数没有意义。
