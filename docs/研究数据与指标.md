# 研究数据与指标

## 班级误区的时间范围（`misconception-2`）

“本周”是北京时间周一 00:00 至当前时刻，不是滚动最近七天。提交按原 `submit_time` 统计，导入时间、标注生成时间不改变归属周。后补的错误标注进入页面数据版本，已打开的页面也会自动重取。评估中的错误想法按被评提交的时间或对应会话最后消息时间归属，旧记录缺少关联时间时沿用评估记录时间。卡点、小题继续按各自原始记录时间统计。总览和误区页共用这一口径，界面仍显示“本周”。

写给论文：要回答哪些问题、每个问题用哪些数据、每个数怎么算（分子、分母、版本）、学期里要做哪些事才收得齐。
代码位置写在每一条后面；导出都在开发者账号的“日志导出”（各页的汇总在那一页右上角“导出”），带学号和姓名，按学号和期末考试系统的成绩对（自己对）。

## 2. 指标定义

每个数都能从导出的记录复算。定义改了就改版本号，导出文件的 `request.versions` 里带着，分析时按版本分段。

### 卡点（`app/stuckstats.py`，版本 `stuck-kp-1`）

一次卡点：学生在求助回合里卡在某个技能上，智能体记下一条。原始记录是技能一层，页面按知识点汇总、展开看技能。

| 指标 | 分子 / 分母 |
|---|---|
| 卡住 | 这个知识点上有卡点的学生数 · 卡点条数 |
| 反复 | 在这个知识点上卡住过两个及以上回合的学生数 |
| 顽固 | 第三次及以上卡在同一个技能上的学生数 |
| 第二次自己想起来 | 第二次卡在同一技能、智能体先请他回忆时自己说出来的次数 / 第二次卡住且已经有结果的次数 |
| 卡后通过 | 卡住时绑定了题、这道题之后在 XDOJ 上通过的次数 / 卡住时绑定了题的次数 |
| 之后新题一次通过 | 第一次卡在这个知识点以后才开始做的、主知识点是它的题（不含卡住的那几道），第一次提交就通过的题数 / 这样的题数 |
| 没来问 | 这个班布置的、主知识点是它的题上，通过前（或到现在）没通过的提交不少于 3 次、却没就这道题开过求助回合的学生数。还在评测的提交不算 |
| 没来问的后来通过 | 上面这些（学生, 题）里，后来在 XDOJ 上通过的 / 全部 |
| 来问的和没来问的（`ask-silent-1`） | 这个班布置的题上，通过前（或到现在）没通过的提交不少于 3 次的（学生, 题）：就这道题开过求助回合（通过后的回顾不算）的算来问过，其余算没来问。各给几题次、几个学生、后来通过的 / 全部、通过的那些一共交了几次（中位数）。描述性的，来问的往往是更难的题、更想做出来的学生，不能读成帮助的效果 |
| 对话行为和做题表现（`dialogue-corr-2`） | 对话至少 5 条、通过至少 3 道题的学生：建构性提问占比、索要答案占比各自和“平均交几次才通过”的皮尔逊相关系数。人数不设门槛（`dialogue-corr-1` 要求至少 8 人，那是拍的数），每个系数附 95% 区间（Fisher z 变换）和双侧 p 值；少于 4 人算不了；区间跨过 0 就是看不出有没有关系。描述性的，不是因果 |
| 用了多少 | 用过智能体：在任何栏目发过消息的学生 / 全班；在作业题上求助：开过绑了题的求助回合的（通过后的回顾不算）/ 全班；反复没过、没来问：有任何一道题算“没来问”的 / 全班 |

“之后新题一次通过”要和对照组比才有意义：导出的提交记录里有每道题第一次提交的结果，可以算同一批学生卡住之前、或没卡住的同学在同一知识点上的比例。

### 每次帮助之后（`app/helpeffect.py`，版本 `help-next-3`）

一次帮助：作业引导里智能体在一道绑定的题上给出帮助的那一步（反问 H0、指出位置 H1、讲原理 H2、给示例代码 H3）。全用程序算，不用大模型。
两次提交之间给了几次帮助的，只算最后那一次（前面的次数记在 `helpsBefore`），这样每次再交只对应一次帮助。

| 指标 | 分子 / 分母 |
|---|---|
| 再交了 | 帮助之后这道题又交过的次数 / 帮助的次数 |
| 下一次就通过 | 下一次提交通过的次数 / 再交了、下一次已经评测完的次数 |
| 下一次结果 | 已评测的下一次提交分四类：通过、仍失败且原错误再次识别、仍失败且未再识别、仍失败且证据不足。分母均为已评测的下一次提交。页面在表下注明多少次失败可比较。 |
| 之后通过 | 帮助之后这道题通过的次数 / 帮助的次数 |
| 隔多久再交 | 帮助到下一次提交的分钟数，中位数（只算再交了的） |
| 到通过交了几次 | 从下一次提交到第一次通过（含）交了几次，中位数（只算之后通过了的） |

这是描述性的：帮助级别是按学生当时的情况选的（卡得越深给得越多），级别之间不能直接比效果。要比效果，要在同样合理的几种帮法之间随机分配，并记下分到的是哪种。

### 系统的决定（`app/decisions.py`，版本 `decision-1`，表 `decision_logs`）

学期末能回放“掌握程度”，但回放不出“系统当时是怎么决定的”（模型和标注之后还会更新），所以决定当时就记下来。每次一行：当时的候选和各自的依据、规则版本、选了哪个、按规则选中它的概率、结果在哪。

| 决定（`kind`） | 规则 | 候选里有什么 | 概率 |
|---|---|---|---|
| 复习先出哪个技能（`review_pick`） | `thompson-1`（2026-11-21 起，之前是 `evidence-priority-1` 固定排序）：每个到期项按 Beta(1 + 会, 1 + 不会) 抽一个数，抽到最低的先试；出不了题的拿掉，在剩下的里再抽（最多三次）。不薄弱的抽查（`spotCheckNotWeak`）只在没有别的到期项时才抽，否则选中概率记 0 | 每个到期项：技能、为什么进复习、分数、档位、Beta 的两个参数（`betaA`、`betaB`）、参数版本、半衰期、超期几天、上次做对的时间、这一次被选中的概率（`pickProbability`）；`context.draws` 是每一次抽签（候选、抽到谁、概率） | 选中那一次抽签里它的概率 P_i = ∫ f_i(x) Π_{j≠i}(1 − F_j(x)) dx，数值积分 |
| 出正确还是有错的代码（`quiz_plan`） | `quiz-plan-2`（2026-11-26 起）：历史作答按课程隔离，再按原有技能、复习范围及正误比例规则选题。之前的 `quiz-plan-1` 可能混入同一学生的另一门课历史 | 有错 / 正确各自的概率；`context` 里有正误怎么定的（`bugRule`）、题型、档位、试了哪些出题器、哪个出的 | 随机概率与原规则相同，按该条记录实际概率分析 |
| 追不追问（`challenge`） | `challenge-random-1`：判断“满足要求”以后以 p = 0.5（`config.QUIZ["challenge_p"]`）抽签 | 追问 / 不追问各自的概率；`ref` 是作答和小题 | 抽到的那一边的概率（0.5） |
| 发不发主动消息（`notice`） | `notice-1`：刚交的没过的提交；卡住了、改对后又犯、普通没过三种 | 三种各自适不适用；`context` 里有第几次提交、错误、离提交几分钟 | 1 |

- 学生自己在复习安排里点了“去复习”：也记一条 `review_pick`，`rule` 是 `student-pick`，`context.by` 是 student、`dueNow` 是当时到没到期；候选只有他选的那一项，概率 1。同一次作答没做完又点“继续”，不再记。分析“系统排序有没有用”时要把这些分开。
- `chosen` 记的是计划。出题器满足不了计划时会退而求其次（比如题库里这个技能没有有错的代码），实际给的另记在 `context.itemHasBug`，对不对得上记在 `context.planMet`：分析“随机分配”时只用 `planMet` 为真的那些。
- 批量补同步的旧提交、很久以前的提交，不是用的时候做的决定，不记。
- 导出类别“系统的决定”，每行带学号姓名，`data` 里有候选、概率、依据和结果编号。

### 通过后的回顾（`chat/summary.py`）

一道题没过、后来改对通过，智能体发总结，最后问“当时卡住的关键是什么”。学生的回答单独一个回合，`endReason` 是“回顾”：

- 挂到这道题前面没过时的技能和错误上，后台照常评“理解”（材料里注明这是通过以后的回顾）；评估的“给到的最多帮助”取这道题通过之前的求助回合。
- 不算求助回合：总览的求助回合数、学生列表的回合数、“没来问”都不算它。导出的求助回合里 `reflection` 为 true。
- 这一句是全部对话里最纯粹的自我解释（题已经过了，没有压力），是通过了的学生“能解释 / 能迁移”的主要证据。

### 解题流程图（`chat/plan.py`，版本 `plan-1`）

还没做的题问“怎么做”时给的流程图。步骤按题存在 `problem_plans`（大模型按题面分的，`source` 是 llm；大模型没给出合格步骤的记 failed、不出流程图；`version`、题面和标注的哈希、生成时间），所有学生看到的同一道题的步骤一样，可以比较。每条引导消息的 `content.plan` 记着当时的进度：选了哪几步（`queue`）、正在讲哪一步（`current`）、讲完的（`done`）、这一步没答上几次（`tries`）；对应的 `chat_steps` 的 `reply.flow` 是 plan（给流程图）或 plan_step（引导一步），`help_level` 是 H0、H1、H2（两次没答上、直接讲清楚）。可以看：学生卡在哪几步多、选了以后交没交、交了过没过。

### 追问（`app/diagnosis.py` 的 `CHALLENGE_VERSION`，`challenge-2`）

小题 protocol 3：判断“满足要求”以后，抽签决定追不追问（`challenge-2`，2026-11-21 起：一半追问、一半直接出反馈；`challenge-1` 是每次都追问）。追问是固定的一句，对正确和有错的代码一样，不透露对错；学生坚持或改判。

| 数 | 分子 / 分母 |
|---|---|
| 坚持（held） | 本来正确的代码判断满足要求、被追问后仍坚持的次数 / 这种情况回答了追问的次数 |
| 改判（turned） | 有错的代码判断满足要求、被追问后改判的次数 / 这种情况回答了追问的次数 |

- 首次判断照样进“判断”；改判以后的选行和修改不进定位、修改的分子分母（不是独立作答），有错的代码改判后改对按 right_second 记进掌握。
- 坚持率低说明判断对了也不确定（知识不稳），改判率高说明一提醒就能自己发现。两者和“把握”（可选）对照看。
- 坚持、改判的分母只有分到追问的那一半。
- 追问的效果按随机分组比：同样判断了“满足要求”的作答，分到追问的和没分到的，比反馈时对不对、之后同一技能的小题和新题一次做对的比例。分组是抽签定的，两组在追问之前没有差别，差值就是追问的作用；每次抽签的概率在决策记录 `challenge` 里，概率改了也能加权。`challenge-1` 的记录每次都追问，没有对照组，只能描述。
- 导出的小题行里有 `challenge`（kept / flipped）、`challengeAssigned`（分到追问 true、没分到 false、没走到这一步 null）、`challengeVersion`，事件里有 challenge、no_challenge、challenge_reply（`keep`）。

### 小题之后的回顾（`app/recap.py`，存在 `quiz_attempts.recap`）

做完一道小题，智能体列出他以前在同一技能（不够时同一知识点）上没过的题和做错的小题，再由大模型分析这几次错在哪、和这道小题的关系。`source` 是 llm（有分析）还是 facts（只列事实）。可以看：回顾之后有没有接着问、之后同一技能的提交和小题是不是好了。

### 判断、定位、修改（`app/diagnosis.py`，版本 `dims-2`）

`dims-2`（2026-11-20 起）：修改 = 看提示之前交的第一稿通过 / 真实错题里交过这种第一稿的次数。先运行公开样例再交的第一稿也算（运行样例是自己测一下，不是帮助）；其中没运行样例就交的另列（`editClean`，就是 `dims-1` 的修改）。看了提示才交第一稿的不进分母，记在“提示或重试后才改对”。导出里的 `firstFixPass`、`firstFixClean`、`events` 都在，两种口径都能复算。
教师端没有数的格子写明为什么（还没做过有错的代码、没看出有错没进入定位、看提示或重试后才改对……），不再写“尚无记录”。

见 [创新点与方法](创新点与方法.md) 5.5 节和 `diagnosis.py` 开头。定位、修改只算独立作答（`protocol` 2），旧版记录不补。

分析学生的代码诊断表现时，按知识点汇总首次判断正确率、实际选行后的首次定位命中率，以及看提示之前提交的首稿通过率（另报其中未运行样例就提交的）。每项同时报告分子、分母和进入该步骤的人数。分析间隔保持时，使用同一知识点的新题表现与实测间隔。半衰期模型的保持值、求助推断的独立性和提交过程算出的改错分可用作选题依据或预测变量。

### 掌握分和每周学的参数（`app/learn.py`，版本 `learn-1`，表 `mastery_params`）

- 掌握分 = (1 + 会) / (2 + 会 + 不会)，会、不会 = Σ 存下的分量 × 可信度 × 这一类证据的系数 × 0.5^(天数 / 半衰期)；档位只看分数（四舍五入后 ≥ 75 已掌握，≥ 50 基本掌握，再低待加强），没有证据才是“还没练过”。
- 系数和半衰期每周学一次：机会 = `prediction_logs` 里每一次“新题第一次提交”，记录时只用了那次之前的证据，结果是那次一次做对没有。损失 = 对数损失 + 先验（log 系数 ~ N(0, 0.5²)，log h0、log g ~ N(log 经验值, 0.5²)），求最大后验。机会不到 60 次也记一版（`learned` 为假），用经验值。
- 每一版冻结：版本是“课程-年W周”（北京时间），记着学到的系数、h0、g、机会数、拟合前后的平均对数损失、每一类出现在几次机会里（`detail`）。一周之内学情、复习抽签、预测都用这一版。
- 好不好看之后的预测，不看拟合损失：`prediction_logs` 每一行同时有这一版算的 `p_score`、经验值算的 `p_score_fixed` 和 `params_version`；研究 · 模型检验按周比两者的 Brier（`scoreBrier`、`scoreFixedBrier`，`nScore` 条）。一版参数只用之前的数据学、只在之后评价，没有拿答案学了再考。

### 图模型（`graph-2026-11-19b`）

后验使用 v2 的作答证据，计入已标注的提交失败和通过可信度。先验只取先修技能的平均掌握，多个先修节点的影响有统一上限。有至少两次尚无改正证据的已标注失败时，才列出有直接证据且估计偏低的先修技能供复查。多人共有的线索按独立学生去重。

图模型通过 `guess + (1 - slip - guess) × 掌握后验` 估计首次通过概率。旧预测保留原版本和数值。分析时以预测日志的 `model_version` 分组。

模型检验可切换预测版本。当前版本展示近六周，历史版本从该版最后一次预测所在的周向前取六周。当前版本没有样本时默认显示最近有记录的历史版本。每次只比较同一版本、同一批首次提交记录。旧版 `2026-11-17a` 的图模型列记录的是掌握估计，其 Brier 只用于历史查看。多维融合和消融仍单独使用同一批有这两项数值的记录。

“反复失败的技能”展示至少两次尚无改正证据的同技能失败。能指出先修技能时加上复查线索，依然缺少具体先修证据时保留原失败记录。

### 导出的字段

导出文件的格式版本在 `request.versions.export`。`logs-3` 增加知识问答教材引用的 `data.textbook`，记录版本（`edition`）、小节（`section`）和位置（`anchor`）。其余沿用 `logs-2`：

- **栏目**可为知识问答、作业引导、复习提升、主动消息（提交没过的提醒、通过后的总结）。对话评估按所属会话标栏目。帮助之后只统计作业引导，因此知识问答关联同一作业题时也不会覆盖那题的作业引导记录。看不出栏目的记录留空。以前的“综合”对话算知识问答；以前插在对话里的小题按它所在的对话算。
- 多一列**代码**，和“原文”一样要勾“包含原文”才有：
  - 提问：学生贴的代码（每段前面一行【标题】；JSON 的 `data.codeBlocks` 里分段给）；
  - 回复：回复里的代码（以前和文字混在“原文”里，现在单独放）；
  - 复习小题：给的代码、首稿、每次运行的代码；
  - 提交：要在“包含原文”下面再勾“包含提交的源码”才有（`data.source`）。
- 勾了“包含原文”，复习小题的 `data` 里再加：`quiz`（题干、给的代码、开始行号、有没有错、错在哪几行、标准改法、解释）、`firstFix`（首稿）、`runs`（每次运行的结果和代码）、`discussion`（反馈后的问答；2026-11-21 起每问带时间 `t`）、`recap`（做完后的回顾：程序整理的事实和大模型的分析），`events` 是完整的事件（不勾时只给时间、种类和几个研究字段）。这些都是系统自己出的题和学生在这里写的东西，不含 XDOJ 的测试点。
- 每条对话的 `data` 里有 `message`（消息编号）、`round`、`topic`（知识问答的主题编号），能把一问一答、同一个主题的对话串起来。

- 小题、复习：`protocol`、`itemVersion`、`judgedHasBug`、`judgeCorrect`、`firstLines`、`locateHit`、`firstFixPass`、`firstFixClean`、`hints`、`sampleRuns`、`events`（记录备题、实际查看、首次判断、首次定位、修改等事件）、`durationMs`、`skipped`。首稿代码勾了“包含原文”才导出（见上）。
  有明确作业提交来源的新作答还会导出 `triggerAt`（提交时间）、`triggerReason`、`phase`（近期检查 recent 或间隔复习 delayed）。首次确认判断时记录 `secondsSinceTrigger`。分析近期与延迟表现应使用这个实测间隔。只有备题或打开过题目的学生还没有首次判断数据。没有历史时间依据的旧记录留空。
- 复习排序 2026-11-21 起是 `thompson-1`（后验抽样，见上面“系统的决定”）；之前的 `evidence-priority-1` 先满足至少一天的间隔。到期后主要看已有作答显示的薄弱程度、反复错误与修改、需要确认独立性的通过。单纯经过较长时间只影响到期时间和同一优先级内的顺序。新生成的复习题记录 `phase=delayed`，以前的 `recent` 记录保留。
- 掌握模型 `2026-11-20`：一道题通过时，次技能分两种。有测试点专门考它的（标注时每个测试点标了主要考哪个技能），按 0.6 算、照常算独立成功；只是顺带用到的，按 0.2 算、不算独立成功（不让半衰期变长，也不能凭它到“已掌握”）。以前一律按 1.0，输出格式、读入这类几乎每道题都用到的技能每过一道题就涨。以前记下的证据后台按新规则重算（`mastery.reweigh_passes`，每条证据带 `algo_version`）。复习也一样：只是顺带用到的次技能，通过一道题不算复习成功。
- 知识点表 0.2（`TAXONOMY_VERSION`，2026-11-21）：知识点拆成单一概念（C 语言 89 个、数据结构 45 个），编码只增不改，技能编码不变，按知识点汇总的指标（卡点、三维、掌握）都按新表算。导出里的 `kp` 是新表的编码；拿 0.1 时导出的文件对比时要换算（`SKILL_KP`）。几个捆了两件事的技能拆开，用到它们的题重标以后，以前的“通过”证据跟着新标注重记，没通过的证据不动。
- 掌握模型 `2026-11-21`：掌握分改成 (1 + 会) / (2 + 会 + 不会)，档位只看分数（≥ 75 / ≥ 50），不再看 80% 区间下限、最近一次是不是独立做对、有没有还没改对的失败；证据的系数和半衰期每周学（`learn-1`）。分数和档位不会再对不上，下面 `2026-11-20b` 说的“分数绿色却是基本掌握”的说明也不需要了。
- 掌握模型 `2026-11-20b`：顺带用到的次技能的通过不算正面也不算反面，不改变“最近一次是不是独立做对”；知识点的档位按这个知识点上最近一条**直接**证据定。以前做题多的同学，最近一条证据几乎总是顺带用到的那种，分数很高却到不了“已掌握”。教师端分数显示成绿色（四舍五入后 75 以上，和分数徽章一致）却是“基本掌握”时写明原因（最近一次没过、最近一次靠提示或示例才过、最近一次通过和同学雷同、做得还不够多）。
- 掌握模型 `2026-11-19b` 保留同一题同技能的递减失败证据。改对后，单次失败保留原权重的 20%，反复失败保留 55%。疑似雷同仍按 40% 计入正向通过证据，不作为独立做对或新增失败。
- 求助回合：`maxHelp`、`helpCount`、`askedBack`、`failedReplies`、`located`、`studentMessages`、`minutes`、`endReason`、`bound`、`reflection`（通过后的回顾，不是求助）。
- 导出 `logs-5` 给问答消息、求助回合和对话理解评估增加 `conversation`。知识问答用 `t<会话编号>`，旧综合问答用 `general`，作业引导用 `p<服务器编号>-<题号>`。按学生、课程、会话串联，同一个会话可有多个回合。即使知识问答关联了作业题，它也属于知识问答。
- 迁移 `0024` 按消息归属拆开历史混用的回合，结束原因标为「会话拆分」。原消息和工作流步骤可供复核，旧的混合评估及相应的学情证据从在线数据库移除。拆分前已经下载的导出及冻结的研究快照仍使用当时的统计口径。
- 卡点：`kp`、`skill`、`nth`、`resolution`、`stubborn`、`passed`、`triesAfter`、`passedAt`、`round`。
- 帮助之后：`level`、`kp`、`skill`、`error`、`rule`、`replySource`、`helpsBefore`、`nextSubmission`、`minutes`、`nextPass`、`errorGone`、`passed`、`triesToPass`、`round`、`step`。
- 理解评估：`basis`、`level`、`rawLevel`、`ruleLevel`、`source`、`confidence`、`adjusted`、`evidenceCount`、`promptVersion`、`reflection`（通过后的回顾评的）。勾了“包括原文”才有摘抄的原话。

## 3. 学期里要做的

1. **开学前定版本，学期中不改**：提示词（`config.PROMPT_VERSION`）、各指标的版本。非改不可时记下日期，分析时分段。
2. **期末导一次全量**：JSON，全部类别，时间段覆盖整个学期。每行有学号，拿学号和期末考试系统的成绩对上。文件里有学号、姓名，按学校的要求保管；论文里出现的表格只用汇总的数，或者自己把学号换成编号。
3. **原文**：只在要做质性分析时勾。学生的话里可能有认得出人的内容，引用之前人工看一遍。

## 4. 局限

- “没来问”的阈值 3 次是定的，不是学出来的；导出里有原始提交，可以换阈值重算。
- “卡后通过”“之后新题一次通过”是描述性的：卡住以后得到的帮助、题目本身的难度、学生自己的努力混在一起，不能直接读成帮助的效果。
- 不做老师盲评、也不收开学基线（2026-11-20 定）：智能体评“理解”的效度只能靠和规则的一致率、按事实下调，以及能不能预测期末上机考试来说明；“用得多的学生考得好”分不清是系统的作用还是学生本来就好。
- 演示数据是编的，上面算出来的数没有意义。

## 开发人员手选考试时间的逐技能回算

模型检验页按班填写外部考试开始时间，统一用北京时间。选多个班时，每个班用自己的在册学生和考试时间回算。各班的证据截止时间取该班考试开始时间与计算时间的较早者，严格排除截止时刻及以后的证据。下载的 JSON 以 `classReports` 按班整理估计、名单、时间、版本、分母和排除记录。若同一学生在多个选中的班，以班级编号和学号关联各自的外部考试，再按考题技能关联逐技能估计。保存下载文件可复查当次结果。

`paired-replay-1` 是固定规则的证据来源对照。对同一学生同一技能，用 (1 + 成功量)/(2 + 观测数) 依次纳入不同 OJ 题的首次提交、对话理解等级/3、复习题的独立判断、首次定位、提示前首稿（题内取已观测步骤的均值，每次完成一步才更新，同题共占一份证据）。均无观测时使用共同先验 0.5，考前技能明细仅列有观测的技能。三组逐条预测同一批新题首交，按机会平均 Brier，按学生有放回重抽 1000 次，计算相邻两组配对差的百分位区间。覆盖人数按首交之前同一技能有无对应来源统计。这些证据对照估计与教学掌握分分别解释。

首交目标要求结果已判定。没有首交时已经存在的题目标注会列入排除清单；历史首交在提交、抓取和标注都已发生后才用于后续估计，标注改版后按生效时间重新归属。首交前学生绑定该题的消息、实际帮助级别与被动收到提醒分开。雷同标记是研究时核查的事后描述，只有通过且指纹达到比对条件才有值，不作为预测输入。没有系统内求助无法排除系统外帮助。

旧夜间预测保留原值。新记录附回算时间、证据截止、首交条件、参数与题目标注版本，融合权重从迁移起留档。旧融合权重无法还原时标明采用默认值。存量证据重新赋权与跨课程边未完整版本化，夜间回算的分数不作为实时盲预测。提交页导出含对应首交的预测来源。严格时序的三模型对照见逐条配对明细。

理解评估页同时报告全部错题机会及独立选行、独立首稿的条件分母。随机追问按原分组统计分配次数、学生人数、见到下一道同技能新题、完成首次判断与判断正确数。未回答下一题计缺测，不跳到更晚完成的题替代。
