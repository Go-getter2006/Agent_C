# Agent_C 网页界面优化方案

日期：2026-11-18。评审基线：`6212d2e`。本文件是设计方案，没有修改业务页面。

建议把产品定位成一个清晰、安静、能追溯学习过程的编程工作台：学生进来知道下一步做什么，教师进来知道谁需要帮助，以及判断依据是什么。

## 2. 当前页面的事实与优先问题

检查了 `Login.tsx`、`Workbench.tsx`、`Thread.tsx`、`Progress.tsx`、教师总览、`KnowledgeMap.tsx`、`KnowledgeGraph.tsx`、`layered.ts` 和设计令牌。

用 Edge 和合成、打码后的演示数据查看了登录、聊天、学情、教师首页、知识图谱，在 1440×1000 和 390×844 两种尺寸保存了截图。本地证据位于工作区 `outputs/design-review`；没有访问真实学生数据。

当前已有值得保留的基础：

- 登录区已有教师/学生身份选择、显示密码、自动填充和加载反馈。
- 对话工作台已有题目列表、题面、提交记录、代码对比和分级提示。
- 知识图谱已有稳定的从左到右分层布局、传递约简、搜索、路径高亮、拖动、缩放、课程区分和图/表切换。
- 色彩和间距已经集中在 `tokens.css`，不需要再引入一套互相冲突的组件主题。

优先解决：

1. **手机边界细节。** 390px 学情页的文档宽度测得 391px；未发现卡片整体越过视口的证据，不能把它描述为严重裁切。作为像素边界细节进一步核查，其他四页未出现该指标差异。
2. **中文字体的一致性。** 当前自行托管的 Inter 主要服务英文，中文依赖系统回退。Windows 和 Linux 不应呈现明显不同的字号感、字重和行高。
3. **操作和数据重复。** 聊天标题、左侧题目、右侧提交区、独立提交页会重复展示结果，需要确定每一处的用途。
4. **图谱默认信息过多。** 合成班级示例有 65 个知识点；全量适应画布后节点文字和分布条较小。需要分层浏览，而不是持续加大画布。
5. **等待状态不够有方向。** 取得代码、题面或评测详情失败时，应说明当前缺少哪份资料、页面是否会自动更新，以及还可以做什么。

## 3. 两个方向及取舍

| | 方向 A：编程学习工作台 | 方向 B：课程学习地图 |
| --- | --- | --- |
| 主要任务 | 继续一道题、阅读代码、获得提示 | 理解课程结构、定位基础薄弱点 |
| 核心画面 | 题目与对话形成主次关系，证据按需展开 | 章节概览 → 知识点 → 局部先修路径 |
| 参考重点 | Codecademy 的编程语境、MGD 的会话组织 | Brilliant 的学习动作、Bloom 的图探索 |
| 视觉表达 | 石墨色文字、白色工作面、少量黄色强调 | 同一套底色；章节分区、节点与路径作为主视觉 |
| 风险 | 资料栏全部展开后对话过窄 | 全量关系展开后再次变成密集网络 |
| 适用 | 登录、学生首页、聊天、代码历史 | 教师知识图谱、学情中的学习路径入口 |

建议以 A 为全站基础，把 B 用在图谱和登录页的产品示意中。全站共用字体、颜色和按钮，页面结构由各自任务决定。

产品的辨识点可以是一条真实的“问题 → 证据 → 尝试 → 改正”学习路径：在聊天里连接提交和提示，在图谱里连接当前知识点与先修知识。它表达产品内容，而不依赖无关的渐变或装饰插画。

## 4. 统一设计系统

### 4.1 色彩

以下是建议值，需要在实现时检查对比度，不是声称从参考站精确测量出的数值。

| 角色 | 建议 | 使用位置 |
| --- | --- | --- |
| 页面底色 | `#F4F6F8` | 工作台背景 |
| 主工作面 | `#FFFFFF` | 表单、题面、对话和图谱 |
| 主文字 | `#17212B` | 标题、正文、主要操作 |
| 次文字 | `#526173` | 时间、说明、次要数据 |
| 品牌黄色 | 沿用 `#FFD43B` | 标识、当前学习路径、小面积强调 |
| 操作蓝色 | `#2463C2` | 文本链接、焦点、定位入口 |
| 边界 | `#DFE5EC` | 栅格、输入区和分隔线 |

通过、错误、等待以及掌握档位继续使用现有语义。黄色不表示警告，也不把所有按钮都染成黄色。颜色必须配合文字或图形；未练到、缺少证据和真正遇到困难分别表达。

### 4.2 字体与密度

- 中文正文建议用本地托管的 Noto Sans SC 或同级别的清晰中文无衬线字体，配置完整的中文回退链。
- 英文和数字可保留 Inter，或统一为 IBM Plex Sans；代码使用 IBM Plex Mono / JetBrains Mono。先比较实际中文混排截图，再决定是否换字库。
- 正文建议 15–16px、行高 1.65；表格与紧凑工具栏 13–14px；页标题 28–32px；代码 13–14px、行高 1.65。
- 统计数字使用等宽数字特性，避免刷新时宽度跳动；长代码只在代码区内部横向滚动。
- 以 4/8px 为间距基础，常用 8、12、16、24、32；正文区最大阅读宽度约 680–760px。
- 不同层级主要靠排版和边界区分；减少每一块都包一张悬浮阴影卡片的做法。

字体参考：[IBM Plex 官方项目](https://github.com/IBM/plex)、[Noto Sans SC](https://fonts.google.com/noto/specimen/Noto+Sans+SC)。落地时核对具体字体文件的许可并采用可维护的子集或字体资源方案。

### 4.3 按钮与控件

| 类型 | 表现 | 例子 |
| --- | --- | --- |
| 主要操作 | 深色实底、白字；每个主区域尽量一个 | 登录、继续练习、发送 |
| 次要操作 | 白底细边框 | 查看代码、比较两次提交 |
| 轻操作 | 无实底或文本链接 | 查看全部、收起、查看说明 |
| 危险操作 | 明确的危险语义色 | 仅用于确实改变或删除数据的功能；本次方案不新增此类操作 |

细节：桌面常规高度 40px，紧凑按钮 32px；手机主要操作目标 44–48px。图标 16–18px，和文字间隔 6–8px，圆角约 8px。图标按钮必须有可访问名称，说明也能由键盘触发。

每一种按钮定义普通、悬停、按下、焦点、禁用、加载、成功、错误八种状态。加载时保留原宽度，显示“正在登录”等明确动作；错误时保留已输入内容并给出下一步。动画建议 120–180ms，避免把缩放和弹跳用于所有按钮。

44–48px 是本项目的舒适触控目标，不应写成 WCAG 的统一强制值；[WCAG 2.2 的最低目标大小准则](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)是 24×24 CSS px 或满足相应例外。

## 5. 登录界面

目标是让学生、教师确定课程与身份，迅速完成登录，而不是阅读宣传长页。

桌面结构：

```text
┌────────────────────────┬──────────────────────────────────┐
│ 标识、课程名           │                    登录表单      │
│ 一句用途说明           │                    课程（如需要）│
│                        │                    学生 / 教师   │
│ 精简的学习过程示意     │                    账号、密码    │
│ 读题 → 尝试 → 获得提示 │                    登录          │
│                        │                    登录说明      │
└────────────────────────┴──────────────────────────────────┘
```

- 左侧约占 40%，右侧表单内容宽约 380–420px。保留深浅对比，减少左侧零散卖点，把现有三条说明合并为一个学习过程示意。
- 保留当前身份切换和课程规则：只有一门课时不额外增加课程选择；不添加无后端支持的 Google 登录、注册或找回密码按钮。
- 主按钮可用“进入学习工作台”或“登录”，两者选定后保持一致；不要在同页混用多个含义相近的主操作。
- 账号标签随身份切换，账号可以保留，身份和课程变化后清除旧错误。支持密码管理器、Enter 提交、显示密码和大小写锁定提示。
- 将“交了题马上能看到结果”改为“提交后自动同步结果”，避免把同步过程承诺为瞬时完成。
- 学生与教师的密码说明必须符合实际行为：学生密码只用于验证；教师数据源凭据会加密保存以进行后台同步，不应统一写成“所有密码都不保存”。
- 手机去掉大面积宣传栏，保留小标识、课程与身份、表单；键盘弹出后主按钮仍可触达。

## 6. 首页：学生与教师分别组织

### 6.1 学生首页

当前登录后主要进入对话工作台，没有必要先做一个营销式首页。可先把未绑定题目时的起始区组织成“继续学习”；如果之后确实需要单独首页，再调整路由。

优先顺序：

1. **继续当前问题。** 显示最近题目、最近一次提交状态、一句进展说明和一个“继续检查”按钮。
2. **到期复习。** 显示要回顾的知识点和预计任务，不重复排列多个同级大按钮。
3. **本次作业列表。** 一行一个作业，显示已通过/总题数、截止日期和进度，支持展开题目。
4. **简短学习反馈。** 有真实证据时说明最近改正的问题；没有数据时使用引导，不编造掌握情况。

避免把提交次数当成能力分数，不加入没有教学依据的排名、奖杯或“学习效率提升百分比”。

### 6.2 教师首页

- 顶部固定课程和班级，先提供“需要关注的人和问题”，再放统计概览。
- 用“重复出现的错误”“还未解决的卡点”“近期缺少提交证据”组织待关注区，并可进入对应学生与记录。
- 核心区域是一张可筛选、可定位的学生表；图表解释趋势，不能挤走可采取行动的信息。
- 保留研究用的模型对比入口，但不要把概率模型和业务结论混成一组醒目的首页分数。
- 不从参考 LMS 中引入当前系统没有的布置作业、评分或发通知功能。

## 7. 聊天界面

把对话作为主要工作面，把题面和提交作为可定位的证据。

```text
应用导航 │ 作业 / 题目 │ 对话与输入区              │ 资料侧栏
         │ 搜索题目    │ 题名 · 当前提交 · 状态     │ 题面 / 图
         │ 最近在做    │                            │ 本次代码
         │ 其他题目    │ 提示 → 代码片段 → 再尝试   │ 历史对比
         │             │                            │ 知识点
         │             │ 输入消息 / 粘贴代码        │
```

- 宽屏可以保留当前四区；中等宽度优先收起资料侧栏，手机一次显示“对话 / 题目 / 记录”中的一个，不把四栏等比缩小。
- 顶部只保留一次当前提交摘要，例如“第 3 次 · 答案错误 · 4/5 组通过”；右侧重点展示代码变化、历史和证据，避免重复完整摘要。
- 题面默认可读，含图时在原位置显示；原始 PDF 是辅助查看入口。文字整理或模型读图能力是否可用，要按实际部署情况判断。
- 为代码、图和对比提供就地入口，例如“查看本次代码”“对比上一次”；保留学生发问时绑定到哪次提交的提示，避免讨论对象不清。
- 助手消息采用清晰的段落、必要的短代码片段和被指出的行；不要给每段消息再套多层卡片。
- 三种帮助动作区分语气与作用：“我再想一想”“给我提示”“讲解这一步”。调整文案时保留既有帮助级别与教学规则，不把最后一项变成索取完整答案。
- 历史提交页仍有版本追溯与代码比较的价值，可弱化独立一级入口；先通过使用数据判断是否合并，不直接删掉功能。
- 输入框自适应到约 6 行，超长内容内部滚动；保留键盘提示、代码粘贴和失败重发，发送按钮在加载期间保持位置。
- 如未来增加流式输出，应定义中止、重试、部分结果和上下文保留规则，不能仅为了“像聊天产品”改成不完整的流式渲染。

等待和错误文案按实际状态分开：

| 情况 | 页面应该表达 |
| --- | --- |
| 正在同步本次代码 | 正在读取本次提交的代码，取得后自动更新 |
| 已有代码，缺少评测详情 | 可以先讨论代码；具体测试结果尚未取得 |
| 题面图不可用 | 说明缺少哪部分内容，保留原始 PDF 查看入口 |
| 网络失败 | 清楚说明当前请求失败，保留输入和重新尝试入口 |

不向学生展示后台任务编号、接口路径、CSRF 等实现信息，也不把隐藏测试输入、标准输出和错误输出直接显示给学生。

## 8. 知识图谱：建议重点改造

### 8.1 先确定图的工作

本项目主要表达课程先修关系与学习证据，推荐继续使用从左到右的有向课程图。Bloom 与 Obsidian 的关联网络可以提供探索交互的思路，但不宜把现有课程图直接改成持续漂动的力导向星云。

默认应回答三个问题：这个知识点之前需要什么、现在有哪些学习证据、接下来适合关注哪里。

### 8.2 三层浏览

| 层级 | 默认内容 | 交互 |
| --- | --- | --- |
| 课程概览 | 章节组及组间关系，少量明确状态 | 选择章节或搜索知识点 |
| 章节视图 | 本章知识点及必要的相邻先修知识 | 选中节点、看局部关系 |
| 局部路径 | 当前节点及 1–2 跳关系，或指定的完整先修链 | 调整范围、返回章节、查看证据 |

缩小画面时显示章节与主关系；放大后显示节点名、状态和细节，这比把 65 个小卡片一次塞进屏幕更有效。1–2 跳是建议的默认范围，不是删除其他关系。

### 8.3 页面组织

```text
班级、课程 │ 全班 / 某学生 │ 章节 │ 搜索 │ 图 / 表
───────────────────────────────────────────────────
章节导航   │ 课程关系画布                    │ 节点详情
           │ 当前节点 + 先修 / 后续路径      │ 概念说明
           │                                 │ 状态与证据
           │                                 │ 相关题目
           │ 缩放、适应、返回概览             │ 关注或练习入口
───────────────────────────────────────────────────
图例、关系含义、证据范围与关系来源
```

当前已经有搜索、缩放、选中详情和图表切换，优先完善其组织与反馈，而不是重复开发。

### 8.4 节点、边和状态

- 默认节点可从当前约 124×46 调整为更能容纳中文的尺寸，例如 168×64；实际尺寸随语义缩放和密度检验决定，不直接把全图放大到更拥挤。
- 名称最多两行，完整名称可在详情和键盘提示中读到。内部知识编码在教师需要时展开，不作为学生的主要标题。
- 班级模式保留档位分布条与人数说明；学生模式明确区分真实作答证据和模型推算。
- 节点填色或状态条表示掌握语义，章节用分组边界与标题表达，避免两套颜色系统抢同一视觉通道。
- 默认边使用低对比细线；选中路径加深、适度加粗并明确箭头。跨课程关系单独使用虚线或既有区别样式，配文字图例。
- 不用边的粗细伪装没有计算依据的“先修强度”，也不把学生成绩改变为图结构。
- “没练到”“暂时没有证据”“待加强”分开显示；关系还是初稿或未审定时保留来源说明。

### 8.5 交互

1. 搜索先给出候选，再定位并高亮，避免每输入一个字整张图重新排列。
2. 单击选择节点，显示直接先修与后续；按需展开间接路径。双击是否进入章节要给出明确提示。
3. 提供“只看当前路径”“查看整章”“回到全图”，并保留返回前的视口。
4. 增加缩略导航或清楚的当前视口指示，便于在较大课程图中找回位置。
5. 节点详情按“它是什么 → 有什么证据 → 哪些题相关 → 下一步可做什么”排列，避免一上来堆统计数字。
6. 图获得焦点后支持键盘定位、选择与缩放；输入框中的快捷键不能被画布截走。
7. 保留现有表格视图作为检索和无障碍替代；手机优先显示局部路径与底部详情，不强迫用户操作完整缩小图。

### 8.6 技术取舍

本轮优先沿用现有 SVG、HTML 节点和 `layered.ts`：已有稳定布局、跨列路由和传递约简，调整信息层级的收益比换库更直接。

如果后续确实需要复杂节点交互、更多布局策略或视口组件，再评估 React Flow 与 ELK。迁移前用真实最大课程规模验证布局耗时、中文标签冲突、缩放与节点可访问性，不能仅凭演示图选择框架。

C 语言与数据结构继续按当前权限隔离。数据结构教师查看 C 语言基础时，只能显示允许的掌握状态，不能借图谱详情开放另一门课的提交和对话。

## 9. 动画、适配与状态细节

- 按钮和菜单反馈建议 120–180ms，侧栏展开约 180–240ms，路径聚焦约 200–300ms；这些是本方案建议值，未通过高级工具测量参考站的动效。
- 画布位置保持稳定，不因筛选着色、选中或后台刷新而重新随机排布。
- 尊重 `prefers-reduced-motion`，减少缩放和位移动画；无需持续滚动、光效和节点呼吸。
- 桌面长面板内部滚动，标题和主要操作保持可见；手机优先一列，并检查键盘、安全区与底部导航的遮挡。
- 加载骨架保持布局尺寸；错误、空状态和证据不足分别设计，不把它们都表现成一个红色报错框。
- 对长题名、长中文标签、多行代码、超多提交、空班级、无作业和慢网络做专门检查。
