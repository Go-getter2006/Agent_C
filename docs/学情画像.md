# 学情画像与代码作品评估（portrait-2 / code-portrait-2）

学生“我的学情”和教师学生详情共用 `LearningPortrait`，数据来自 `progress.build`。保留原来的做题事实、下一步、每周提交、数据结构的 C 基础与知识点卡片，新增四图概览。旧的全部知识点列表折叠保存，旭日图中的细项也使用相同的卡片。

## 能力图的证据边界

这些是描述性指标，不是经过效度检验的统一心理测量，不写回 `SkillEvidence` 或改变掌握模型。说明仅放开发者“模型说明”，不在学生或教师页面加入算法说明。

| 维度 | 当前计算与分母 | 能说明与不能说明的 |
| --- | --- | --- |
| 程序理解 | 优先代码理解评估，缺少时用对话评估，档位/3的平均；两者均无时优先用OJ作品中的概念应用量规，再列复习首次判断 | 有记录的理解表现；模型量规需要人工验证，判断正确也不等同于能解释 |
| 方案设计 | 当前各不同题的代表作品中，适用、置信度至少0.5的设计量规/3平均 | 作品采用的策略符合题意与约束，不证明独立设计 |
| 编码实现 | 已通过的不同题/尝试过的不同题；另列首交通过数 | 练习完成表现，不声称独立通过 |
| 测试验证 | OJ代码中题意要求的边界与特殊情况处理量规/3平均；无作品量规时用复习首次判断 | 已处理与遗漏的情形；不证明学生主动设计过测试 |
| 调试修复 | 曾出错而后来通过的不同题/曾经出错的不同题；另列独立首稿修改 | 改错结果，不把接受帮助后通过包装成独立修复 |
| 效率分析 | 当前不同题的适用作品量规/3平均 | 本题条件下代码开销的适配程度，不证明学生能独立推导数量级 |

无数据返回 null。图不补零，不跨缺失轴闭合，不把未作答当作低能力。上述维度异质，不相加为总能力分；比较前后或开展科研时须保留题目、样本量、量规版本与帮助条件。对话与复习仅作为有实际记录的补充。

## 知识掌握

继续使用 v2 的知识点档位和 `KpState.score`，不以图模型后验 p 代替掌握分。按最终确认的交互复用同一个圆环：点击扇区后从该扇区连续扩展到完整圆环，依次展示最多四个知识大类和细知识点；面包屑返回时反向收拢。悬停或聚焦立即显示名称、数量及占本层比例；按实际掌握分调整同档颜色，点开显示原知识卡片与实际掌握程度。总览圆心是全部知识点中已掌握项的占比；展开的局部图圆心为本组已评分知识点的平均掌握程度。

C 语言四类为语言基础、流程控制、数据组织、函数算法；数据结构为基本概念、线性结构、树与图、查找排序。都是显示分组，不修改技能表、知识粒度或先修边。

## 误区热力图

横轴是八类知识领域，纵轴是既有错误类型的八类粗映射（见 `portrait.ERROR_PATTERNS`），不调用额外模型做归类。记录来自当前版本且置信度至少0.5的提交标注、已完成小题中首次没认出的错误、已有理解评估中的误解。同一提交、同一错误、同一领域的重复标注去重。代码错误与概念误解仍保留来源，不把二者混成学生原话。

默认本周，北京时间周一零点起，按提交时间、原作答时间、原会话时间归属；导入、标注或评估延迟不改变归属周。非本课程、未知技能、其他错误 OT99、低置信度标注不入矩阵。格子是记录数而非错误率；没有练过的领域显示 —，练过但当前范围无这种记录显示 0。点击格子能看实际记录。

## 代码风格与复杂度

每个自然周、每道题只选最后一份通过稿；该周没有通过稿则选最新已完成评测的稿。不能按提交次数加权，不取未来记录。六个风格项为排版规范、命名清晰、常量表达、控制结构、函数组织、重复冗余，不评注释数量。量规0/1/2/3表示严重缺陷、部分达到、达到题目要求、清楚充分；不适用或无法判断为 null，置信度不足不汇总。

每周各适用题等权平均档位/3。历史最低/最高轮廓分别取各项周均值极值，可能来自不同周，不是某个整体画像，也不是置信区间。本周仍在进行，题目组合、样本量和分析完成情况均影响结果，不能仅据曲线变化宣称干预有效。无本周提交时显示最近有记录的一周，并标“最近一周”。

时间、空间复杂度按题展示源码、输入规模定义、假设、推导与引用行号。程序整体包括函数、递归、库调用；不能按循环嵌套层数直接冒充复杂度，不能因 O(n) 自动扣分，不能虚构运行耗时与内存。短题不强制拆函数，合理短变量名不直接扣分，适用性由量规记录。

## 云端存储、更新与调用成本

- `code_analyses`（迁移0025）持久保存指纹、量规版本、模型名、状态、结果、重试次数及时间。服务重启和浏览器刷新均复用云端结果。
- 页面请求不调用模型，只为被查看学生的周代表稿排队并读取结果；不在发布时自动付费回填整班历史。
- 指纹包含源码、题意、评测结果、模型名和量规版本。相同题、相同内容复用。页面读所有题时一次预载源码与题面，避免逐份分析重复查询。
- 已启用画像的学生有新提交时，`pipeline.process_submission → codequality.on_submission` 自动更新对应周的代表稿；同题同周未处理的旧稿标 superseded，保留记录。已经完成的评估保留。
- 独立后台线程每30秒检查一次，不阻塞同步。每次只分析一道题的一份代表稿及它之前去重的修改轨迹，完成后立即接下一稿；不把整周量规塞进一个输出。所有模型名从原有 `config.DEEPSEEK_MODEL` 获取，没有新增硬编码模型名。
- 未通过稿以原提交后10分钟作为连续修改合并窗口，新的修改会替换同题同周尚未处理的旧稿，通过稿不等待该窗口；已完成分析的相同输入直接复用。
- 输出不设额外token上限，保留接口默认值，单次不立即重试；失败延迟15分钟再试，最多三次，失败后不生成模板评分。修改模型配置或输入会产生新指纹。
- 每个非null结论必须给有效源码行号、文字依据及置信度。排版另保存缩进规则对照；规则不替换模型分析，其余语义指标没有规则就不伪造一致率。正式科研仍需人工抽样量规复核。
- 用途、输入输出tokens与失败原因沿用 `llm_calls` 记录。日志导出新增“代码画像评估”，带版本、模型、指纹、状态和结果。未勾原文不导出理由或源码行，源码受原有“包含源码”开关控制。

### 最终交互与接口格式验证

用户进一步确认复用单环的放大钻取。圆心百分比与扇区角度使用同一进度，前进320ms、返回240ms，三次方ease-out；快速反向操作从当前显示数值和几何形状继续。键盘与prefers-reduced-motion立即完成，不伪造无评分项的0值。浏览器逐帧记录了实际扇区路径和中间百分比，验证正反向与中途返回。

真实接口还暴露了0温度下过长输出、括号不配对和引用越界的问题。代码画像请求使用0.3温度（其他调用默认值保留）、带明确当前行号的输入、合法JSON例子，以及DeepSeek官方beta严格函数格式。函数参数采用扁平字段减少嵌套，仅作为模型结果的传输格式；保存时映射回量规结构。模型名继续读取环境变量，不新增输出token上限。

格式读取仅允许“已完整解析的对象之后多余结束符”，不修改对象里的文字、数字或行号，也不补缺失字段；记录格式备注。对象内部坏语法、额外对象或截断仍拒绝。量规逐字段核验，合格字段持久复用，只补不合格字段；不生成固定分析。真实接口已保存一份10项量规与复杂度的完整结果，输出1633 tokens；这不是仅用模拟模型验证。模型分析仍需人工抽样复核，量规不构成独立能力的效度证明。
