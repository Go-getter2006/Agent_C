# 设计审查记录（界面重做）

你看了上一版的界面，打分 30/100，发来四张参考图，说“具体还是你来定，但总之要合理”。这一版把学生端、教师端的界面全部重做了一遍。截图在 [screenshots/](screenshots/) 里，文件名是“页面-宽度”，用的是演示数据。

## 0. 做了什么

| 步骤 | 情况 |
|---|---|
| 找参考 | 看了你发的四张图；用搜索看了数据面板和图谱交互的写法。站点本身在这个环境里打不开，见 [references.md](references.md) |
| 定设计令牌 | `frontend/src/styles/tokens.css`：颜色、字号、间距、圆角、阴影都在这里，组件里不写死 |
| 重写页面 | 学生端：登录、对话、提交、复习（新页面）、学情。教师端：总览、学生、学生明细、卡点、知识图谱（新页面）、模型对比、日志申请（新页面）、数据源 |
| 多设备检查 | Playwright 在 390、768、1280、1440 四个宽度打开每一页，检查横向溢出和脚本报错，见第 1 节 |
| 交互检查 | 点求助按钮、发消息、复习里开始做题、选把握、判断、改代码、运行检查，全程没有脚本报错 |
| 对比度 | 按令牌的颜色计算，见第 2 节 |
| 对照你的设计规范 | 哪些地方没按规范做、为什么，见第 3 节；规范明令禁止、又没有带来什么好处的几处改回来了 |

## 1. 多设备检查

| 宽度 | 学生端 | 教师端 |
|---|---|---|
| ≥1440 | 深色侧边栏展开（236，带文字）+ 题目列表 + 对话 + 右栏 | 侧边栏展开 |
| 1280–1439 | 侧边栏收成图标竖条（76）+ 题目列表 + 对话 + 右栏 | 侧边栏展开 |
| 1024–1279 | 竖条 + 题目列表 + 对话；“这道题”收进右侧抽屉 | 竖条 |
| 768–1023 | 竖条 + 对话；题目列表和“这道题”都收进抽屉 | 竖条 |
| <768 | 对话占满；底部标签栏四项；点题目名换题，点结果那一行看这道题 | 深色顶栏，左上角按钮打开导航抽屉 |

| 检查项 | 结果 |
|---|---|
| 页面主体没有横向滚动 | 通过。所有页面四个宽度溢出都是 0。中途查出过一次：表头里给读屏用的隐藏文字是绝对定位，跑出了表格的滚动区，给滚动区加 `position: relative` 修好了 |
| 宽表格、代码块、知识图谱在自己的容器里滚动 | 通过 |
| 脚本报错 | 没有（未登录时取当前用户的那次 401 是预期的） |
| 触控目标 | 手机上按钮、输入框、发送键、标签栏都是 44 或以上 |
| 键盘 | 所有按钮、知识图谱里的每个知识点都能用 Tab 走到；焦点有 2px 蓝色描边；抽屉和详情面板按 Esc 关闭 |
| 减少动效 | 抽屉滑入、“正在输入”、骨架屏闪动都包在 `prefers-reduced-motion: no-preference` 里 |
| 一屏布局 | `html, body, #root` 用 `height: 100%`，不用 `100vh` |
| 首屏体积 | 代码编辑器（CodeMirror）改成按需加载，学生打开页面时主包从 678 KB 降到 266 KB（压缩后 83 KB）；教师端单独一个包 |

## 3. 和你的设计规范不一样的地方

规范（《设计规范（A 工作台）》）里有不少“禁止”。你说这版“具体还是你来定”，所以我按“好不好用、合不合理”逐条判断：有理由的保留了，下表写清楚；规范明令禁止、改了也没带来什么的，改回来了。哪条你不同意，告诉我就改。

### 保留的改动

| 规范 | 现在 | 为什么 |
|---|---|---|
| 2.3 不用阴影，层次靠底色和分隔线 | 卡片有一层很淡的阴影（`0 1px 2px` 4% 黑），弹层有正常阴影 | 页面底改成了冷灰，内容放在白卡片里。没有阴影时卡片和底色的边界在低质量屏幕上看不清 |
| 4.1 导航只有三项，不放头像、不放徽标 | 学生端四项（对话、提交、**复习**、学情）；侧边栏顶部有产品标志，底部有姓名和退出 | 复习是这次新加的功能，需要一个入口；退出登录原来藏在学情页里，不好找 |
| 4.1 宽屏导航是 72 宽的竖条 | 很宽时展开成 236 宽、带文字；中等宽度还是竖条 | 你发的参考图都是展开的侧边栏；学生端在 1440 以下仍是竖条，给对话留宽度 |
| 4.3 对话不用气泡、不用头像 | 学生的话靠右、浅灰气泡；智能体的话靠左，前面是产品标志，上面写“智能体” | 一长串对话里一眼分清谁说的。智能体用的是产品标志，不是机器人头像 |
| 2.2 字重只用 400 和 600 | 加了 500，用在按钮、标签、表头 | 只有两档时按钮和正文分不开 |
| 2.3 圆角 4px | 控件 10px，卡片 14px | 和参考图一致；4px 的卡片在冷灰底上显得生硬 |
| 黄色只用于当前选中 | 黄色用在产品标志、小题标签上的小图标、复习的图标；当前选中改成白色药丸 | 深色侧边栏上白色药丸比黄色更清楚；黄色变成品牌色，用得很少 |
| 图标是 1.8 线宽的自绘图标 | 换成 lucide 图标库（开源，ISC 许可） | 自绘图标只有十来个，不够用 |
| 6.10 不用圆点拼元信息 | 教师端表格里的小字还在用“·” | 教师端信息密，句子太长。学生端全部改回了逗号连起来的短句 |
| 教师端的大数字指标卡 | 总览、模型对比用了 | 规范只禁止学情页用；老师需要一眼看到这周的变化 |

## 4. 学生能看到什么（信息边界）

这次改界面时顺手查了一遍，并加了测试：

- 测试点只有过没过：格子是实心绿（过）或空心红框（没过），没有悬停提示，没有输入输出。
- 不显示概率：复习页原来的提示写着“现在记得大约还有 8%”，**这是上一轮留下的错误**，已经改成文字（“还记得比较牢 / 开始有点模糊 / 可能快忘了”）和三段条；接口里也不再返回这个数。测试里加了一条：复习页和“接下来做什么”的返回里不能出现百分号。
- 学情页“第一次提交就通过占 25%”是学生自己的做题事实，不是模型估计，保留。
- 不显示技能编码、工作流步骤、跨课程内容、模型名称。知识图谱、v1/v2 对比、数据结构准备度只在教师端。

## 6. 已知的问题

- 这个开发环境只有文泉驿正黑，没有粗体，截图里的中文标题看起来不够粗。在装了微软雅黑、苹方的电脑和手机上是 600 字重。
- 知识图谱在手机上缩到 0.62 倍，要拖着看；手机上建议切到“表”。
- 知识图谱是“一章一行”的固定排法，跨很多行的先修边会穿过中间几行（被知识点卡片挡住一部分）。默认把边调得很淡，悬停或选中时才亮起来。
- 演示数据里几乎没有“已掌握”：v2 要求 80% 区间的下限不低于 0.6，每个技能只做过两三题的学生达不到。真实数据多了以后会好一些；要不要放宽，见[问题清单](../问题清单.md)。
- 日期输入框的显示格式跟着浏览器的语言设置走。
- 教师端在手机上能用，但主要还是给电脑用的。
