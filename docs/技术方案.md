# 技术方案

这份文档说明系统现在是怎么搭的：技术栈、目录、数据表、模块之间怎么配合、哪些是程序定的哪些交给大模型，以及后面还要做什么。和设计文档不一致的地方、需要确认的地方在 [问题清单](问题清单.md) 里。

## 1. 技术栈

| 部分 | 用了什么 | 说明 |
|---|---|---|
| 后端 | Python 3.11+、FastAPI | 和总说明的建议一致 |
| 数据库 | PostgreSQL 16（正式）；SQLite（本机开发、测试） | SQLAlchemy 2 + Alembic。表结构两种库通用 |
| 后台任务 | 常驻主循环：默认在网页进程里的一个后台线程（`SYNC_IN_WEB=1`）；docker compose 里单独一个容器（`python -m app.cli daemon`） | 同步、标注、学情证据、夜里更新图模型。主循环每 20 秒写一次心跳，同时只允许一个在跑，“数据源”页据此提示同步有没有在运行 |
| 前端 | React 18 + TypeScript + Vite | 样式全部是自定义的 CSS 变量（`styles/tokens.css`），没有用组件库；图标用 lucide；图表和知识图谱是手写的 SVG；可编辑代码用 CodeMirror 6（按需加载） |
| 大模型 | DeepSeek，经 `app/llm.py` 统一调用 | 结构化输出、程序校验、重试、提示词带版本号、记录耗时和费用 |
| 沙箱 | gcc + rlimit；正式环境在独立容器里 | 只跑我们自己的小题代码和参考解 |
| 部署 | 试用：`./run.sh`（Linux，一条命令装好并启动）。正式：Docker Compose：db、web、daemon、sandbox，可选 caddy 自动 HTTPS | 服务器上只需要 Docker |

## 2. 数据怎么流动

```
XDOJ ──只读──> 同步（xdoj/）──> 原始数据表 xdoj_*
                                   │
                    详情取齐后入队 post_process
                                   ▼
              pipeline.py：没通过 → 标错误类型（labeling/）
                           第一次通过 → 记学情证据（mastery.py）、结束回合、看要不要出小题
                                   │
        ┌──────────────────────────┼───────────────────────────┐
        ▼                          ▼                           ▼
   对话工作流（chat/）          小题（quiz.py）            学情（progress.py、graphmodel.py）
   取证 → 规则表 → 回复         沙箱运行判分               学生端四块；教师端分布和图模型
        │                          │
        └────── 卡点、作答结果都写回 skill_evidence ──────────┘
```

网页进程和后台进程只通过数据库打交道：网页往 `sync_triggers` 写一行，后台主循环来取。

见 [README](../README.md) 末尾。后端按功能分包，没有分层套娃：一个功能的表、逻辑、接口大多在两三个文件里就能看完。

## 4. 数据表

全部定义在 `backend/app/models.py`，共 41 张。

**XDOJ 原始数据**（主键都带服务器标识 `server_id`，两台服务器的编号互不影响）

| 表 | 内容 |
|---|---|
| `xdoj_servers`、`data_sources`、`class_sources` | 服务器；数据源（服务器 + 教师账号，密码加密）；哪个数据源能看到哪个班 |
| `xdoj_classes`、`students`、`enrollments` | 班级；学生（学号全局唯一）；学号 × 班级 × 学期 × 课程 × 服务器 |
| `xdoj_contests`、`xdoj_contest_classes`、`xdoj_contest_problems` | 作业、布置给哪些班、包含哪些题 |
| `xdoj_problems`、`xdoj_problem_tags`、`xdoj_problem_texts`、`xdoj_testcases` | 题目、标签、题面（原文件和抽出的文字）、测试点（输入输出原样保存） |
| `xdoj_submissions`、`xdoj_source_snapshots`、`xdoj_judges`、`xdoj_judge_runs`、`xdoj_run_outputs` | 提交、源码、评测记录（重判是新行，`is_latest` 标出最新）、测试点运行、失败点的程序输出 |
| `xdoj_archive` | 题面或测试点内容变了，覆盖之前把旧内容存这里 |

**同步状态**：`sync_state`（进度，按服务器分别记）、`sync_fetch_queue`（任务队列，优先级 0~3）、`sync_triggers`、`sync_request_log`（只有接口、状态码、耗时）。

**账号**：`users`（管理员、教师、学生）。

**标注**：`problem_labels`、`testcase_labels`（带版本，旧版本不删）、`reference_solutions`、`submission_labels`、`label_candidates`、`llm_calls`。

**对话**：`chat_rounds`、`chat_messages`、`chat_steps`（每条学生消息的 8 步结果）、`stuck_points`。

**小题**：`quiz_items`、`quiz_attempts`、`revisit_queue`。

**学情**：`skill_evidence`（每条进入计算的证据）、`graph_posteriors`、`prediction_log`（后两张只给教师端用）。

**界面事件**：`ui_events`。

数据库迁移在 `backend/alembic/`。本机开发时启动会自动建表；正式环境用 `alembic upgrade head`。

## 5. 各模块

### 5.1 XDOJ 同步（`app/xdoj/`）

| 文件 | 做什么 |
|---|---|
| `client.py` | 会话、登录、接口白名单、全局串行限速、被转到登录页时自动重登、指数退避。只有被转到登录页才算掉线；接口回 400 错误页或不是 JSON 是 `ResponseError` / `ClientError`，只让当前任务失败、退避重试，不让整个同步停下来 |
| `endpoints.py` | 每个接口一个函数，只留需要的字段；名单里的密码、令牌、IP 在这里丢掉。参数照网页里 jqGrid 实际发的写：顶层表格 POST、开关叫 `search`；展开的子表（作业里的题、测试点、评测记录）GET，固定用实测过的 `_search=false`、`sidx=`（空）、`sord=asc`、`page`、`rows`、`nd`（`grid_json`），不猜写法。2026-11-18 实测：评测记录缺 `sidx`、`sord` 时返回 500，补齐后 200。评测 `judgement` 的 0/1/2/3、测试点 `result` 的 1~6 在这里换成文字（两套不能混用） |
| `sync_meta.py` | 每位老师：班级 → 名单 → 作业（几十个请求），**每两小时自动一次**；发现不认识的学生交了题、交到了不认识的作业里、或者有人用名单里没有的学号登录时，马上自动再同步一次（10 分钟内不重复）。题库是同一台服务器上所有老师共用的，**按服务器一天同步一次**：只拉题目列表、比对题目信息；要下载测试点和题面的题排进队列（作业里用到的优先），每道题只下载一次，别的老师登录不再重复。比对哈希发现新题和改动，入队重新标注 |
| `sync_submissions.py` | 按进度 H 取新提交（和 H 的前移在同一个事务里）、取详情、评测未完成的跟进、回读。详情里源码最先取、不依赖评测记录；每组程序输出单独取；有一步出错，拿到的先存下，任务退避后重试 |
| `store.py` | 进度、任务队列。XDOJ 那边出错的任务按 2、4、8…分钟退避（最长 6 小时）；退避用完的详情、题面和测试点任务，启动时和每天夜里自动重新入队 |
| `daemon.py` | 主循环：触发 → 名单（到时间就同步）→ P0 → 轮询（三档）→ 未评测完 → P1 → 本地任务 → P2 → 回读和夜里的任务 → P3；都没事时做本地的自动工作（`automation.py`：结束超时的对话回合、评“理解”、写评语） |
| `api.py` | 给网页进程用：`notify_student_active`、`request_priority`、`request_meta_sync`、`request_meta_sync_if_stale` |
| `assemble.py` | 组装证据 JSON（含测试点原始数据，只在后台用） |
| `fake.py` | 假的 XDOJ，测试和演示数据用 |

**题面整理**（`app/pdftext.py`，**不用 OCR**）：XDOJ 的题面是 PDF，都带文字层，不是扫描件。但直接复制文字常常不对：多余的空格和断行、行的顺序乱、上标下标被拆开（`10^5` 抽成“10 5”）、`≤ ≥ ×` 丢了，个别字体还会出乱码。本系统先抽本地文字层，再交给模型整理；DeepSeek 也提供独立的[文件解析接口](https://api-docs.deepseek.com/guides/document_parsing/)，当前没有调用它：

1. 抽文字：文字层用 pdfplumber（按行，知道位置）和 PDFium（浏览器用的那个库，有些字体解得更对）各抽一遍，挑乱码少的；编码错位（UTF-8、GBK 被当成 Latin-1 解）程序直接还原；汉字之间多出来的空格去掉。已核对的 Wingdings 箭头按字体还原为 `→`，避免把整篇题面误判为乱码；旧缓存自动重抽，学生优先请求的提交会先处理该题面。
2. 示意图：PDF 里的图片、成片的线条（画出来的示意图）从渲染好的页面上裁下来存成 PNG（`xdoj_problem_figures`），文字里在那个位置写 `[图1]`。里面密密麻麻全是字的框（样例框、表格）不算图，分隔线不算图。只是把那块区域截下来给学生看，不识别图里的字。
3. 大模型整理：修抽取造成的问题，分出题目描述、输入格式、输出格式、样例、提示；样例逐字照抄；不许加原文没有的内容。程序核对（不靠大模型自己说）：数字只能来自原文、原文的数字九成以上要在（样例不能丢）、`[图N]` 一个不少、汉字九成以上来自原文、长度相当、整理后不是乱码。不合格重写一次，还不行就用程序抽的文字。在标注这道题之前做（标注用整理好的题面），后台空闲时也补；每个文件只整理一次，原文（`raw_text`）留着。数学式子（范围、上下标、幂、分式、求和）整理成 LaTeX，用 `$...$`、`$$...$$` 包起来；样例和 C 代码、运算符不写 LaTeX。程序另外核对 `$` 配对、公式里没有汉字。

   整理要求改了（比如这次要求公式写成 LaTeX）就改 `pdftext.TIDY_VERSION`（现在是 `latex-1`）。以前整理过的题面，后台空闲时按新要求各重整一次（`pdftext.retidy`，每分钟最多两道）：题面按（服务器, 题目）存在 `xdoj_problem_texts`，这台 XDOJ 上所有老师、学生共用，每道题只调一次大模型；学生、老师打开页面只读库，不会触发整理。核对不过就保留原来的文字，也记下版本，不再重试；大模型没连上（网络、接口错误）不记，下一轮再试。只是排版变了时原来的标注照旧有效，不重新标；以前乱码、这次才读出来的重新标注。`cli doctor` 会列出还有几道没按新要求重整。

学生端显示（`components/Lists.tsx` 的 `Statement`）：小标题加粗、比正文大一号；公式用 KaTeX 排（跟着前端打包，只带 woff2 字体，题面里有公式时才加载，不连外网）。以前整理好、没写 LaTeX 的题面，程序认得出的常见写法（`1 ≤ n ≤ 1000`、`1<=n<=10^5`、`10^9+7`）也排成公式，认不出的照原样，`if (a<=b)` 这类 C 代码不动（`lib/statement.ts` 的 `mathPieces`）。样例一律原样。
4. 原文里有认不出的乱码（字体没有文字对照表）时，大模型能按上下文还原，但没法和原文核对，状态记“大模型还原了乱码（没法核对）”；没有大模型时乱码的文字不显示。学生端直接显示题目，不让学生点开 PDF：文字整理得出来就显示文字（按小标题分段，样例等宽显示，示意图在原来的位置）；整理不出来就直接显示 PDF 的各页（渲染成图、裁掉页边空白，`/api/problems/{key}/pages/{n}`）。

读题面一律经过 `usable_text`：乱码不会给学生看，也不会发给大模型、拿去标注；发给大模型时 `for_llm` 会说明 `[图N]` 是它看不到的示意图。以前的程序存下的 PDF 题面，后台空闲时自动重新抽一遍（原文件存着，不用再请求 XDOJ），文字变了就重新标注。

### 5.2 标注（`app/labeling/`）

- 没通过的提交：先过规则（编译诊断的关键词、去空白后一致、输出等于正确值截掉小数等），规则判不了才交给大模型，而且只能从错误类型库里选。编码不在库里就整条作废重标一次，仍不合法记 OT99。
- 题目：简述、1 个主技能、最多 4 个次技能、每个测试点考什么和“哪类情况”。参考解优先用同学的通过提交；没有时让大模型写，在沙箱里用全部测试点跑通才算数。
- 结果直接使用，没有审核关卡；改了记新版本。

### 5.3 对话工作流（`app/chat/`）

对话线程有三种：某道作业题（`server_id`+`problem_id`）、知识问答的一个主题（`chat_topics`，消息记 `topic_id`）、以前的综合对话（都为空，知识问答里叫“以前的问答”）。知识问答（`workflow.handle(..., knowledge=True)`）不自动绑题，学生选了“结合当前题”（`pin`）才绑，没绑题又没贴代码的问题按概念问题答，也不出小题。

| 步 | 文件 | 谁做 |
|---|---|---|
| 1 消息分析 | `analyze.py` | 大模型（输出按枚举校验）；没有大模型或不合格时用规则；点按钮不用分析 |
| 2 绑定、3 取证、4 诊断、5 状态 | `context.py` | 程序 |
| 6 策略 | `policy.py` | 程序。规则表是纯函数，不查库 |
| 7 生成 | `reply.py` | 大模型；没有时用固定模板（`hints.py`） |
| 7 校验 | `validate.py` | 程序。附件一 5.7 的 8 项；不通过重写一次，再不通过用模板 |
| 8 收尾 | `workflow.py` | 程序。回合、卡点、小题、证据 |

写回复的大模型每次都拿到完整的情况（`context.tutor_context`，只在配了大模型时取）：

- 题目原文和这道题的全部测试点，没通过的那几组另外带上他程序的输出（`llm.evidence_for_model`），都**不截断**；没取到的是 `null`，和“空输出”分开；
- 他的完整代码（发生在哪次提交就是哪次）和这道题每次提交的经过（“第 2 次：答案错误，问题：变量没给合适的初值，比上一次改了 1 行”）；
- 学情：这门课里还薄弱的知识点和标记（例如“改错靠试”）；
- 他在别的题上纠结过的地方：别的题上的卡点（和最后是怎么解决的）、智能体评估时记下的误解。只取同一门课的。

标注提交的错误、标注题目、对比两种做法、看代码评“理解”时也一样：题面、测试点、源码、改动完整给出，没取到的标 `null`。只去掉学号、姓名等身份字段。提示词要求测试数据绝不原样告诉学生。`validate._leaks` 对这道题**全部**测试点的输入输出做检查，回复里出现了就重写，两次不行退回模板。学号、姓名不进提示词。

**每次提交改了什么**（`app/changes.py`）：每一次提交和他上一次提交逐行比（`difflib`），学生端直接显示“改了 2 行（第 10~11 行）”、改动的那几行（只有他自己的代码，最多 6 行）、“修好了：……”“还在：……”“新出现：……”（错误的名称，来自程序标注）。改了一半以上或者 20 行以上算大改，只说改了多少行，不摘代码。

**通过后的总结**（`chat/summary.py`）：一道题前面没过、后来通过了，智能体在这道题的对话里说的是“你是怎么改对的”，不再问哪里卡住：交了几次、前面的问题是什么、最后一次改的那几行，最后问一句“回头看，你觉得当时卡住的关键是什么？”。如果是大改（多半换了一种做法），有大模型时让它对比两种做法（原来的思路、现在的思路、原来的写法问题出在哪），再问他为什么换；没有大模型时直接问。对比也要过测试数据的泄露检查。只对两天内的新通过、每道题一次；紧接着要出小题时去掉回顾的那一问，不同时问两件事。

**主动消息**（`chat/proactive.py`）：同步到一次没通过的提交、标完错误以后，两种情况智能体会先在这道题的对话里说一句：又犯了以前在别的题上改正过的同类错误（摘出那道题、他当时改对后的那几行代码，让他对照）；同一道题第 3 次以上没过而且错在同一处（问要不要一起看）。只对两小时内的新提交；他正在这道题上说话时不插嘴；每人每天最多 4 条（`config.PROACTIVE`）。

### 5.4 小题（`app/quizgen.py`、`app/quiz.py`、`app/quizbank.py`、`app/sandbox/`）

作答协议（`quiz_attempts.protocol`，迁移 0010）：新出的题都是 2，独立作答——确认判断（把握可选）→ 选位置或依据（一行或连续几行，`locate_hit` 只在真有错且判断有问题时算，选太多行不算命中）→ 判断有问题的修改（`sample` 只跑第一组检查数据、不算提交；`hint` 一条比一条具体，代码本来就对的题不说破；`submit` 可以原样提交）→ 反馈（`feedback2`）。首次判断、首次选行、首稿（`first_fix`、`first_fix_pass`、`first_fix_clean`）各记一次；所有动作按顺序进 `events`；`item_version` 记题目内容的哈希。反馈之前学生端拿不到有没有错、错在哪、标准改法、解释，也不标改动的行。结果映射回原来的 outcome（right / right_bypass / right_second / wrong_fix / right_judge / wrong_judge），掌握程度的算法不变。protocol 1 的旧记录照旧显示、照旧能做完。复习提升进来就有题：`review.prepare` 按到期顺序试着出一道（一项出不了换下一项，都出不了退避 5 分钟），后台空闲时 `review.prepare_active` 给最近来过的学生提前备好；侧边栏的数字是 `review.ready_count`。

**按学生的情况出题**（`quizgen.py`）。先定“出什么”：考哪个技能、他在这个技能上犯过哪几种错、最近出过的题里没错的占多少（让没错的代码占四到五成，免得学生一律答“有错”）、出判断题还是改错题（档位低、或刚忘过的出改错题），他是不是“自以为会”（很有把握却答错过）。再按顺序找题：

1. 改他自己的代码：从他这道题（或同一技能的别的题）通过的代码里摘几行，按他犯过的错误做一处改动（初值、循环边界、比较符号、强制转换、`long` 换成 `int`、格式串……），问“改成这样还对吗”；
2. 让大模型现场出一道（只给技能、错误类型，不给学号姓名）；
3. 用模板题换变量名和数据；
4. 最后才用题库里的固定题。

每道题都在沙箱里验证：有错的版本真的出错，没错的版本和标准改法真的通过。检查用的输入是把原题的测试点输入做小的扰动生成的，期望输出用他自己通过的代码和参考解各跑一遍、两者一致才用，所以学生看不到也推不出原题的测试数据。

题库里每道题有显示的代码、隐藏的模板和检查数据。入库前验证：有错的代码真的出错，没错的代码和标准改法真的通过，选择题里只有一个选项是对的。学生改完后，后端先做静态检查（改动不超过 3 行、不能有预处理指令和文件、进程、网络调用），再放回模板在沙箱里编译运行。学生端在作答结束前拿不到“有没有错”“错在哪一行”“标准改法”。

### 5.5 学情

- `diagnosis.py`：判断、定位、修改三维（界面改造方案第 5 节），每个数都从 `quiz_attempts` 复算。判断 = 首次判断正确 / 提交了首次判断（错题识别、正确代码识别分开）；定位 = 首次选中有效位置 / 真实错题里判断有问题、提交了首次选行（只算 protocol 2）；修改 = 没看提示、没运行公开样例就交的第一稿通过 / 这种第一稿的次数（只算 protocol 2）。另列应答机会、进入定位、进入修改、提示或运行后才改对、跳过、没做完、旧版记录（protocol 1，标“旧版未测定位”，不拿后来改了哪行补首次定位）。不和掌握分配权重，掌握程度照旧，三维只用来解释。学生端（`progress.build` 的 `dims`）只有知识点名称、几比几、一句话；教师端学生明细（`diagnosis`）有拆分、各种次数和最近一次作答的证据链（判断 → 首次所选行 → 修改与提示、原代码和所选的行、动作顺序）；知识图谱节点详情有全班三行和每个学生的一行（`diagnosis`、`studentDims`）。
- `mastery.py`：两个版本，证据一条一条存在 `skill_evidence` 里，档位在查询时现算，所以改权重不用重算历史。
  - v1：附件一第 8 节的简单算法，保留作对照。
  - v2（默认，`MASTERY_MODEL=v2`）：在 v1 的证据上加四件事。① 可靠性：通过的代码和班里更早的通过规范化后一样、写法少见、时间挨得近，这次通过按 0.4 计（`similarity.py`）；② 个人化的遗忘：每个学生每个技能有自己的证据半衰期，隔天以上的独立成功让它变长，失败让它变短；③ 图先验：用先修知识点的掌握程度给一个 Beta 先验（包括跨课程的先修），证据少时不至于乱跳；④ 80% 区间：“已掌握”要区间下限不低于 0.5（大约三道题一次做对或很快改对）且最近一次独立做对；⑤ 改对算会：一道题前面没过、后来自己改对了（这道题通过了，或者后来交的时候这个技能上的错已经改掉了，比如缺分号改掉了、现在错在算法上），前面的失败只按 0.2 算，错在别的技能上的、改对它算一次“会”；“待加强”要有**还没改对**的失败、而且估计低于 0.5，或者改对过又犯（别的题上改对过，新的题上又错、还没改对）。以前失败一次记 0.5、改对只记 0.8，交两次才改对的同学反而成了“待加强”，几乎人人待加强。会话（智能体评的理解）一直是 v2 的证据，按置信度计入估计值。
  - 题目还没有大模型标注时（没配、题面没整理好、标注失败），按 XDOJ 自带的标签、类别、作业标题、题目标题兜底标注（`labeling/problems.tag_label`，程序确定，来源记为 tags），做对的题照样记证据，知识图谱照样知道作业覆盖了哪些知识点；大模型标好后取代它。以前因为没有标注没记上的“第一次通过”，后台空闲时自动补记（`pipeline.backfill_passes`）。
  - 教师端的“掌握分”（0~100）：只看学生自己的证据（做题、会话、小题），用很轻的先验 Beta(0.5, 0.5)，不掺图先验，能把做得好和做得一般的同学分开；档位仍按上面的规则定。学生列表、学生明细、知识图谱的节点（全班平均，或者选中的那个学生）都有。学生端不显示分数。
  - 每个知识点一句话（`kpdesc.py`，程序从数据里数出来）：每个学生一句（做过几道、一次做对几道、交几次改对几道、还没过几道，对话里讲不讲得清，常错什么），全班一句（一次做对、改对、还没过各占多少，改对平均交几次，常错）。教师端知识图谱的节点详情里有全班一句和每个学生一句，选中某个学生时他那一句放在最上面；学生明细里每个知识点一句；学生端学情页每个知识点是自己那一句。数据结构还没开课，用 C 语言的先修推算“准备度”，只在教师端显示。
  - ⑤ 智能体评估的“理解”（`assess.py`）也是 v2 的证据，见下面。只改估计值、不算练过；v1 和图模型不用这类证据，v2 也可以去掉它（`include_agent=False`）做消融。
  - 几个版本、图模型、多维融合、“v2 去掉智能体评估”对同一批“下一次能不能一次做对”做预测，教师端研究 · 模型检验按周比 Brier 分数。
- `assess.py`：智能体评估“理解”，全自动。对话回合由后台自动结束（超时、或者题已经通过——学生走开了也会结束），结束后（后台空闲时、或每天夜里）大模型读学生在这个回合里自己说的话，按量规评 0 不理解 / 1 能照做 / 2 能解释 / 3 能迁移，附上学生原话。防乱评：原话必须一字不差出现在他的消息里，否则退回重写；评到 2、3 档必须有原话；和程序能确定的事实冲突时下调（回答问题一次没答对过却评“能解释”→“能照做”；看了示例代码才改对却评“能迁移”→“能解释”），下调原因留给老师看。同时用规则算一个等级（只看答没答对、通没通过），用来算两者的一致率（Cohen's κ）；没有大模型时用规则的等级，但规则的等级不另记证据（它用的事实已经在做题证据里了，避免重复计算）。发给大模型的内容不带学号、姓名；学生端看不到评估。
- **只在 OJ 上交题、从不问智能体的学生也有完整的分析**（他可能就是会，不需要问）：
  - 没通过的提交是证据（`mastery.record_failed_submission`，只在 v2 用）：记到出错的那个技能上（程序或大模型标注的主错误），同一道题同一个技能第一次没过 0.5、第二次 0.25，再往后不记。自己改对的通过在 v2 里按 0.8 算（原来是一次做对的一半）。
  - 改错过程（`process.py`）：每道题从第一次提交到第一次通过是一段过程，看交了几次、同一个错误是不是紧接着又出现、是不是不到一分钟就重交，算出 0~1 的“改错”分数。
  - 智能体看代码评理解（`assess.assess_code`）：一道题没过、后来自己改对了、没问过智能体的，大模型看从最后一次没过的代码到通过的代码改了什么，按同样的四档评；评到 2、3 档要摘抄改动里真实存在的代码行；急着重交、同一个错误反复出现的下调。规则也给一个等级对照。只评最近两周的。
- 不再把“第一次就通过的比例”当主要指标：OJ 上先交上去看看很正常，格式小错也算没过。学生端和教师端换成“平均几次改对”（通过的题平均交到第几次通过）；“需要留意的学生”按“通过一道题要交的次数明显比全班多”。模型检验仍然用“新题的第一次提交能不能通过”当预测目标，因为那是任何反馈之前最干净的信号（知识追踪的常见做法），只用来比模型、不给学生打分。
- `profile.py`：多维掌握画像。每个知识点七个维度：做题（v2）、理解（智能体评估：问过问题的看对话，没问过的看代码怎么改的；按置信度和 30 天半衰期加权）、独立（通过前要了多少帮助）、改错（OJ 上的改错过程）、保持（复习的半衰期回归）、自知（小题的把握和对错是否吻合）、前置知识（知识图上前置技能的估计，图节点辅助）；另附贝叶斯网络的后验作对照。融合：有数据的维度取 logit 加权相加；权重起点是经验值，攒够 30 次预测后，每天夜里用带收缩的逻辑回归按“下一道新题能不能一次做对”重新学（每门课一组，`model_weights` 表）。先记预测、后学权重，评比不拿答案学了再考。还有六种提示（会做讲不清、多靠提示、快忘了、自以为会、先修没打牢、先修扎实但这里是缺口）。
  - 学生端：知识点卡片展示掌握档位、做题记录和练习入口。每道小题的具体反馈在复习页查看。
  - 教师端：学生明细里的画像表、智能体评估记录（含原话、下调原因、规则对照）、对话行为；总览“需要留意的学生”加上“会做但讲不清”；研究 · 模型检验有融合和消融的 Brier、学到的权重，研究 · 理解评估有一致率，研究 · 求助效果有对话行为和做题表现的相关。不再给每个学生写评语：老师没有时间逐个看，同一页的知识点表已经有档位、一句话和提示；大模型用在分析上。
  - 对话里：大模型写回复时能看到这个学生在这个知识点上的画像（一句话），据此调整讲法。
- 对话行为（`chat/analyze.py` 的 `dialogue_act`，参考 StudyChat）：概念提问、带着想法问、只说错了、索要答案、要提示、解释自己的想法、想自己想、简短回应、说不会、问题意、其他。由意图、有没有自己的想法、按了哪个按钮定，记在 `chat_steps.act`；回答智能体的问题时答到点上没有记在 `chat_steps.answer_correct`。
- `review.py`：复习，借鉴半衰期回归（HLR）的间隔重复。每个复习项有自己的半衰期，记得的程度按 2^(−天数/半衰期) 算，降到 0.75 时到期；答对按把握程度把半衰期乘 1.5~2.5，答错减半；学生自己又独立做对同一技能也算一次复习；连对三次且半衰期超过 20 天算巩固；每天最多两道。学生端只显示“还记得比较牢 / 开始有点模糊 / 可能快忘了”，不显示数字。
- `stuckstats.py`：卡点按知识点汇总（版本 `stuck-kp-1`）。原始记录还是技能一层（`stuck_points`）。谁卡在哪个知识点在知识图谱：表里有“卡住过”“没来问”两列，知识点详情里有“卡在这里”；比例在研究 · 求助效果（`/classes/{班级}/help`）。每个知识点：卡住几个人几次、反复（两个回合以上）、顽固、第二次自己想起来（几比几）、卡后通过（卡住时那道题之后在 XDOJ 上过没过）、之后新题一次通过（第一次卡在这里以后才开始做的同知识点题），另列“没来问”：一道题没通过的提交不少于 3 次、没就这道题求助的学生。学生明细的卡点表也带上知识点和“之后通过了吗、又交了几次”。定义见 [研究数据与指标](研究数据与指标.md)。
- `rating.py`：老师盲评“理解”（教师端研究 · 理解评估）。材料和大模型看到的一样（`assess.dialogue`），不显示学生是谁、大模型和规则的等级；选一档就记下（`human_ratings` 表，0011 迁移）、换下一条，“看不出来”单独记。同一页的“一致率”算老师和大模型原始等级、约束后等级、规则等级的一致率（完全一致、差一档内、κ、二次加权 κ），下调过的离老师更近还是更远，两位老师之间的一致率。
- `progress.py`：学生学情页的四块。
- `graphmodel.py`：贝叶斯网络，吉布斯采样。每天夜里全图更新一次，并记下两个模型对“下一次能不能一次做对”的预测，教师端按周比较。

### 5.8 两张知识图（`app/taxonomy/`）

C 语言（`knowledge.py`、`skills.py`）和数据结构（`ds.py`）各一张图，先修边在 `prereq.py`：C 语言内部、数据结构内部、从 C 语言到数据结构的跨课程边分开写，载入时检查没有环。教师端“知识图谱”页：C 语言的班只有 C 语言这张图；数据结构的班是数据结构这张图，可以“加上 C 语言基础”（只带这门课要用到的 C 知识点，跨课程的边用橙色虚线）。节点按全班的档位分布或某个学生的档位着色。

**怎么在知识点很细的时候也看得清**（`frontend/src/lib/layered.ts`，Sugiyama 分层画法的简化版）：

- 从左到右是学习的先后：每个知识点放在它最长前置链的那一列；没有前置知识的点往右挪，挨着它的后续知识。两门课一起看时 C 语言在左、数据结构在右。
- 跨好几列的连线在中间每一列占一个看不见的中转点，连线只走列与列之间的空隙，**不从知识点底下穿过**；每一列的上下顺序用重心法来回排多轮、再逐对交换，留交叉最少的；纵坐标用保序回归让每个点尽量和邻居对齐，长线被拉直。
- 能由别的路径推出来的连线（A→B→C 时的 A→C）不画，详情里照样列出；和谁都不连的知识点放在下面一块。
- 聚焦：平时连线是浅灰细线；鼠标停在一个点上，它直接的前置（蓝）和后续（黑）亮起来；点一下选中，整条前置链和后续链亮起来，其他的退到后面，被详情挡住时图自己挪开。位置只由数据决定，换着色、搜索、按章筛选、选中时都不动。

用演示数据量过：C 语言这张图以前（一章一行）57 条连线里有 25 条从别的知识点底下穿过，现在 0 条，相邻两列之间一共 17 处交叉；数据结构从 14 条变成 0 条（5 处交叉）；两门课一起看从 40 条变成 0 条。

参考：[分层画法（Sugiyama）](https://en.wikipedia.org/wiki/Layered_graph_drawing)、Gansner 等的 dot 算法（中转点、重心排序、相邻交换）、[Van Ham 和 Perer 的“搜索、显示上下文、按需展开”](https://aviz.fr/wiki/uploads/Teaching2015/SearchShowContextArticle.pdf)（聚焦加上下文）。接口是 `/api/teacher/classes/{班级}/knowledge-map` 和 `.../knowledge-map/{知识点}`。

跨课程的联系（`cross.py`，`cross_links` 表）：`prereq.py` 里的跨课程边是人工初稿，启动时写进表里。之后全部自动（`cross.auto_links`，每天夜里）：智能体给还没提过的数据结构知识点补充联系（四种类型：先修、被用于、是其中一部分、相似），把握 ≥ 0.7 的直接采用，其余先“待检验”；用“新题一次做对”的记录检验每条联系（C 那头掌握了和没掌握的两组比较，Beta 后验）；待检验的、数据支持的自动采用，智能体提出的、数据不支持的自动不用。老师在“跨课程”页可以改（可选），改过的以老师为准。采用的联系按“类型 × 数据检验”加权进入 v2 的图先验，有跨课程先修的技能先验分量 n0 更大，所以数据结构的估计 = η·C 那头给的先验 + (1−η)·自己的证据。“跨课程”页还有 C 基础预警；学生明细有“联合状态”；数据结构学生的学情页有“要补的 C 语言基础”（只有档位）。接口：`/api/teacher/classes/{班级}/cross`、`/api/teacher/cross/{id}/review`（老师改，可选），C 语言登录时都是 404。

### 5.9 日志申请（`app/logs.py`）

参照库道（DBEDU）“按需获取学生查询日志”的数据处理方式：老师选学生（自己名下的班或填学号）、时间段、记录类型，写一句用途，系统生成一个 7 天有效的下载链接（CSV 或 JSON），每次申请和下载都记进 `log_requests`。不在名下的学号跳过并在结果里列出；提问和回复的原文默认不给，要单独勾选；“样例”一列只有“没通过第几组”，没有测试数据；不含密码、令牌、登录 IP。限额：一次 500 个学号、366 天，每人每天 20 次。

研究用的导出：一律带学号和姓名，不做化名（老师要按学号和期末考试系统的成绩比对，比对由老师自己做）；JSON 里带各指标的版本。另有三类记录：求助回合（最多帮助、反问几次、没答上几次、学生说了几条、用了几分钟、怎么结束的）、卡点（按知识点，之后过没过、又交了几次）、理解评估（大模型原始和约束后的等级、规则等级、下调原因、老师盲评的等级和用时）；小题、复习带独立作答的全部字段（首次判断、首次选行、首稿过没过、提示和运行的先后）。字段和指标的定义见 [研究数据与指标](研究数据与指标.md)。

### 5.10 前端

教师端的速度：教师端的请求里，同一个学生“现在”的掌握状态只算一次（`mastery.memoize`，存在这次请求的数据库会话上；以前总览给每个学生每个知识点各算一遍，12 个学生要 300 多次）；总览、学生、知识图谱、模型检验、求助效果、跨课程这几页的结果按“数据版本”缓存（`app/web/cache.py`：几张会变的表的最大编号和最近更新时间都没变、也没超过 2 分钟，就用上次的），定时刷新大多数时候不用重算。前端切回一个页面先显示上一次的数据（`useLoad` 的 `memoKey`，只在内存里，换账户或退出就清掉）。页面不各自定时刷新：只有一个地方（`common.tsx` 的 `useVersionTicks`）每分钟问一次 `/api/teacher/version`（看不见页面时不问，切回标签页马上问），数据变了页面才重取，数据没变最多十分钟重取一次（“本周”这类按时间算的数）；切回已经取过、数据没变的页面不再请求。演示数据上总览从 0.75 秒降到 0.15 秒，数据没变时 7 毫秒；停在一页十分钟，请求从 20 次（每分钟重取页面和班级列表）降到 10 次很小的版本询问加 1 次取页面。

`frontend/src/`：`styles/tokens.css` 是全部设计令牌，两套纸面按 `<html data-course>` 切换（C 语言暖色、数据结构冷色，首页和登录以后共用），字体（得意黑、Atkinson Hyperlegible Next、Maple Mono）在 `main.tsx` 引入、跟着前端打包，标题字体的规则在 `styles/type.css`；切换作业、题目时先留着上一份内容（淡一点），新的取到再换，不闪白（`useLoad` 的 `keep`）；菜单和题目列表的选中底色从原来那一项滑到新的一项（`components/Slider.tsx`）；`components/` 里是外壳（墨色或深蓝侧边栏、手机底部标签栏）、首页和对话空白处的立体场景（`CourseScene.tsx`）、对话、小题、图表（`charts.tsx`）、知识图谱（`KnowledgeGraph.tsx`）；`pages/` 是学生端页面，`pages/teacher/` 是教师端（单独打包，学生不会下载）。设计上和规范不一样的地方见 [design/审查记录](design/审查记录.md)。

## 6. 贯穿全程的要求是怎么落实的

| 要求 | 落实 |
|---|---|
| 对 XDOJ 只读、限速 | 白名单写死在 `client.py`；限速器按服务器共用；间隔不能设到 0.2 秒以下 |
| 学生密码、令牌、登录 IP 不落盘 | `endpoints.list_students` 只取三个字段；其他接口的原始 JSON 存之前过 `scrub()`；有测试扫全库和日志 |
| 发给大模型的内容不带学号姓名 | `llm.strip_identity()`；有测试 |
| 原始数据只追加 | 重判是新行；题面、测试点改动先归档 |
| 标注、提示词、模型、算法参数带版本号 | `config.py` 里的各个 `*_VERSION`，写库时一起存 |
| 统计字段来自固定的表或枚举 | `taxonomy/`；大模型输出逐字段校验 |
| 学生看不到步骤、编码、概率、测试点数据 | 学生端接口只返回整理过的视图；有一个测试把学生端能拿到的内容全取一遍来扫 |
| 能确定判断的不交给大模型 | 输出比对、编译诊断、小题运行判分、规则表 |
