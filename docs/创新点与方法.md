# 创新点与方法

这个系统的研究部分做两件事：

1. **刻画学生对每个知识点的掌握程度**：多维度、多方法，智能体（大模型）参与评估，而不是只看对错的固定公式；
2. **知识图上的算法权重和图模型构建**：C 语言、数据结构两张知识图，以及两门课之间的联系（跨课程部分见第 5 节）。

下面先说和已有工作的关系，再逐条说做了什么、怎么检验、有什么局限。代码位置写在每一节里。

## 1. 已有的工作

| 工作 | 做了什么 | 和这里的关系 |
|---|---|---|
| 知识追踪（BKT、DKT 等） | 从做题对错的序列估计掌握程度 | 只用对错。分不出“会做”和“懂了”，也分不出“自己做出来”和“看了提示才做出来” |
| Qu 等（2019，Entropy 21:1216） | 在线评测上的多任务 LSTM；提交先后、快速提交、抄袭和成绩相关 | 借用了两个特征：提交名次（教师端“学生”页）和雷同通过打折（掌握程度 v2 的可靠性） |
| Han 等（2025，TransKT） | 跨课程的知识追踪：大模型零样本给两门课的概念建立带类型的联系，再用图网络和对比学习得到联合状态 | 跨课程部分的出发点（第 5 节）。这里的区别：联系要经过数据检验和老师确认；联合状态用可解释的贝叶斯更新，不用黑箱网络 |
| McNichols 等（2026，StudyChat） | 课程里真实的学生—大模型对话；对话行为分类；概念性提问和成绩正相关、索要答案负相关 | 借用了对话行为的分类，把它接进学生模型（第 4 节） |
| 用大模型当评分者（LLM-as-a-judge） | 让大模型按量规打分 | 已知的问题是会编造依据、和人的判断不一致。这里用“必须引用原话”“和事实冲突就下调”“和规则对照算一致率”三条约束（第 2 节） |

以前也有人做过跨学科、跨课程的分析（TransKT 就是）。这里不重复“两门课一起建模”本身，重点放在：**智能体怎么可信地参与评估、多个维度怎么按数据定权重、跨课程的联系怎么验证**。

## 2. 创新点一：智能体参与评估“理解”，每个结论都锚定在学生原话上

代码：`backend/app/assess.py`。

**问题**：会照着提示改对、但说不出为什么的学生，下次换个样子很可能又错。“懂没懂”只能从学生自己说的话里看出来，程序判断不了。

**做法**：一个求助回合结束后，大模型读学生在这个回合里自己说的话，按固定量规评四档：0 不理解、1 能照做、2 能解释、3 能迁移。防止乱评的三条约束：

1. **证据锚定**：评到 2、3 档必须摘抄学生原话，原话要一字不差地出现在他的消息里，否则作废重写（参考以证据为中心的评价设计：每个结论都要指着证据）。
2. **事实约束**：和程序能确定的事实冲突时下调——回答智能体的问题一次也没答对过却评“能解释”，降到“能照做”；看了示例代码才改对却评“能迁移”，降到“能解释”。下调原因留给老师看。
3. **规则对照**：同时用规则算一个等级（只看答没答对、通没通过、要了多少帮助），计算两者的一致率和 Cohen's κ，在教师端公开。一致率太低说明要检查提示词。

评估结果记成掌握程度的证据：会 / 不会按等级记，分量乘大模型给的置信度；只改估计值、不算“练过”，所以只聊过没做过题的技能不会因此有档位，会做但讲不清的，估计值和区间下限会被拉低，不容易到“已掌握”。只有大模型读了原话得出的评估才记证据；规则的等级只用来展示和对照——它用的事实已经在做题证据里了，再记一次是重复计算。

**和“大模型只用来聊天”的区别**：大模型在这里是测量工具，它的输出进入学生模型，并且接受一致率和消融（第 6 节）的检验。

## 3. 创新点二：多维掌握画像，维度权重按数据学

代码：`backend/app/profile.py`。

七个维度，每个维度的数据来源和算法都不同：

| 维度 | 数据 | 方法 |
|---|---|---|
| 做题 | 评测结果（通过和没通过的都算）、提交次数、求助级别、雷同 | Beta 后验（v2）：可靠性加权、个人化遗忘、知识图先验、80% 区间 |
| 改错 | OJ 上的提交过程 | 交了几次改对、同一个错误是否反复、是否急着重交 |
| 理解 | 对话里学生自己说的话；没问过的，看他怎么改代码 | 智能体按量规评估（第 2 节），按置信度和 30 天半衰期加权 |
| 独立 | 通过之前要了多少帮助 | 一次做对 1、自己改对 0.85、反问或指位置后 0.6、讲原理后 0.3、给示例代码后 0 |
| 保持 | 复习记录 | 半衰期回归：2^(−天数/半衰期) |
| 自知 | 小题前选的把握和实际对错 | 1 − 平均 |把握 − 对错|；偏差为正是高估自己 |
| 前置知识 | 知识图上的前置技能（学它之前要先会的） | 前置技能估计的加权平均（图节点辅助）；另附贝叶斯网络的后验作对照 |

**融合**：把有数据的维度取 logit 加权相加，再变回概率。权重的起点是经验值；攒够 30 次预测以后，每天夜里按“下一道新题能不能一次做对”用带收缩的逻辑回归重新学，每门课一组。收缩（往经验值拉）保证数据少时不会乱跳。**先记预测、后学权重**：当天记下的融合预测用的是学之前的权重，评比时不会“拿答案学了再考”。

学到的权重是公开的（教师端研究 · 模型检验），能回答“对这个班来说，哪个维度最能预测表现”。

**可解释的提示**：会做讲不清、多靠提示、快忘了、自以为会、先修没打牢、先修扎实但这里是具体缺口。老师看到的是这些话和对应的数值；学生看到的是每个维度三段的条和一句话，没有数字。

**用在哪里**：学生学情页、教师端学生明细和总览；对话里大模型写回复时也能看到这个学生在这个知识点上的画像，据此调整讲法（讲不清原因的多问为什么，常要提示的先让他自己说）。

### 没问过问题的学生

没问过智能体不代表有问题，可能就是会、不需要问。所以掌握程度不能依赖对话：

- **没通过的提交也是证据**：记到出错的那个技能上（比如题考求最值、错在下标越界，记到“下标访问”），同一道题上分量递减，交得多不会被无限扣分；
- **改对算会**：后来自己改对了的题，前面的失败只算一小部分，改对本身算“会”；只有还没改对的、或者改对过又犯的，才是“待加强”。一次做对、交几次改对、会话里讲得清不清，都是掌握程度的一部分；
- **改错过程**（`backend/app/process.py`）：每道题从第一次提交到通过，交了几次、同一个错误是不是反复出现、是不是不到一分钟就重交（Qu 等 2019：快速提交和成绩负相关），算成“改错”维度；
- **智能体看代码评理解**：没过、后来自己改对的题，大模型看他是怎么改的——改动是不是正对着出错的原因，还是大段重写、反复试出来的。和看对话一样的约束：评到 2、3 档要摘抄改动里真实存在的代码行，急着重交、同一个错误反复出现的下调。

“第一次就通过的比例”不再当主要指标（OJ 上先交上去看看很正常，格式小错也算没过），学生端和教师端换成“平均几次改对”。

## 4. 创新点三：对话行为进入学生模型

代码：`backend/app/chat/analyze.py`（`dialogue_act`）、`profile.dialogue_profile`。

参考 StudyChat 的分类，把每条消息归为：概念提问、带着想法问、只说错了、索要答案、要提示、解释自己的想法、想自己想、简短回应、说不会、问题意、其他。由消息分析的意图、有没有自己的想法、按了哪个按钮确定，不额外调用大模型。

- 每个学生：建构性的（概念提问、带着想法问、解释自己的想法、想自己想）占多少，索要答案占多少；
- 每个班：这两个比例和一次通过率的相关系数（描述性，样本不够不算），用来在本校数据上检验 StudyChat 的结论；
- 回答智能体的问题时答没答到点上，记在每一步里，也是“理解”评估的事实依据。

## 5. 创新点四：跨课程的联系要经过检验，联合状态可解释

代码：`backend/app/cross.py`、`mastery.py`（v2 的图先验）。

两门课分开登录、分开显示：C 语言里不出现数据结构；数据结构里可以看学生在 C 语言相关知识点上的掌握程度（只有档位和估计），不出现 C 语言的答题记录。在这个前提下，借鉴 TransKT 的两个想法——带类型的概念联系、联合的知识状态——但换了做法：

**带类型的联系，自动提出、自动检验**。C 语言技能和数据结构技能之间的联系分四类，和 TransKT 一致：前置（Prerequisite_of，学 B 之前要先会 A，1.0）、用到（Used_for，B 里直接用到 A，0.8）、组成部分（Part_of，A 是 B 的一部分，0.7）、是一种（Hyponym_of，A 是 B 的一个特例或一种具体做法，0.6）。人工初稿的每条联系都写了为什么成立（比如“指针定义与初始化 → 链表结点”）。来源有两种：人工初稿（28 条）和智能体提出。每天夜里智能体自动给还没提过的数据结构知识点补充联系（大模型读两门课的技能表，编码只能从表里选、不能和已有的重复，不合格退回重写）：把握大的直接采用（还没检验时分量打七折），把握不大的先“待检验”，等数据支持了再自动采用；智能体提出、数据不支持的自动不用。TransKT 直接用大模型零样本建的联系；这里大模型是提议者，数据是把关者，全程不需要人去点。老师可以改（可选），改过的以老师为准。

**每条联系都用数据检验**（自动，每天夜里）。每天夜里，对每条联系把学生分成两组：C 那头的估计 ≥ 0.6（掌握了）和 < 0.6，比较两组在数据结构这头“新题一次做对”的比例，用 Beta(1,1) 后验算“掌握了的那组更高”的概率。两组合起来至少 10 次才下结论：概率 ≥ 0.9 算数据支持，≤ 0.5 算数据不支持，其余算还不够。结论决定这条联系在模型里的分量（支持 1.0、还不够 0.7、不支持 0.3），也显示给老师，作为修正知识图的依据。

**联合状态是可解释的贝叶斯更新**。数据结构技能的先验均值 m 是先修技能估计的加权平均（权重 = 类型 × 数据检验）；先验的分量 n0 相当于几次作答（默认 2 次，再乘联系的分量）。于是

  估计 = η·m + (1−η)·自己的证据，η = n0 / (n0 + 2 + 数据结构这头的证据量)。

刚开课时 η 接近 1，主要看 C 基础；做的题越多，η 越小，越由数据结构自己的表现决定。教师端学生明细逐个知识点列出“自己的证据、C 基础、η、合起来”。TransKT 用的是可学习的融合系数和图网络；这里每一项都能解释给老师听。

**能直接用的东西**：
- C 基础预警（数据结构的班）：按这个班作业涉及的知识点，列出全班最薄弱的 C 基础（几个人薄弱、影响哪些知识点），以及需要先补基础的学生；总览“需要留意的学生”加上“C 语言基础薄弱”。
- 数据结构的学生学情页：“要补的 C 语言基础”，只有档位和一句话（“学「单链表」要用到，C 语言里这块还要再练练”），没有数字、没有 C 语言的记录。
- 知识图谱：数据结构的班可以“加上 C 语言基础”，只带这门课要用到的那些 C 知识点，跨课程的边来自采用的联系。

## 5.5 判断、定位、修改分开测（界面改造方案第 4、5 节）

小题不再只记“做对没有”。学生先独立判断代码满不满足要求，再自己选出问题所在的行（或支撑判断的行），判断有问题的再改。首次判断、首次选行、首稿各记一次，运行公开样例、看提示按顺序记下。这样能分开回答三个问题：认不认得出错、找不找得到错在哪、改不改得对；也能区分“第一稿直接通过”“自己运行后改对”“看了提示才改对”。正确代码和错误代码按题组接近各半发放，正确代码也有完整的结束页，界面本身不会因为提前结束而泄露答案。三维每个数都能从导出的作答记录复算，定位和修改的分母只算实际进入这一步的次数，不当成全体能力估计；暂不和掌握分配权重（`app/diagnosis.py`）。

## 6. 怎么检验

都在教师端的研究页（模型检验、理解评估、求助效果），预测按周统计，越小越好的 Brier 分数为主：

- **v1 / v2 / 图模型 / 多维融合** 对同一批“新题的第一次提交能不能一次做对”的预测；
- **消融**：v2 去掉智能体评估的证据（`include_agent=False`），看智能体评估有没有让预测更准；
- **一致率**：智能体评估和规则等级的完全一致率、相差不超过一档的比例、Cohen's κ；
- **老师盲评**（`app/rating.py`，教师端研究 · 理解评估）：老师看和大模型同样的材料、不知道学生是谁和大模型评了几档，按同一个量规评；算老师和大模型原始等级、约束后等级、规则等级各自的一致率（含二次加权 κ），约束下调过的那些离老师更近还是更远（检验“原话锚定、和事实冲突下调”有没有用），两位老师之间的一致率当上限；
- **权重**：融合学到的每个维度的权重和默认值的对照。

- **跨课程联系**：每条联系两组学生的一次做对比例、后验概率和结论（“跨课程”页）。

测试（`backend/tests/test_profile.py`、`backend/tests/test_cross.py`、`backend/tests/test_automation.py`）覆盖：后验比较的计算和“样本不够不下结论”、数据支持的联系分量更大、老师不用的联系不再进先验、待检验的联系不进先验、智能体自动补充（把握大的自动采用、数据支持的自动采用、每个知识点只提一次、老师改过的不动）、对话回合在学生走开后自动结束并评估、智能体编造的编码被退回、η 随数据结构的证据变多而变小、C 语言登录看不到跨课程页、数据结构学生的学情页只有档位；编造的原话会被退回、和事实冲突时下调、大模型不合格时退回规则、智能体证据不产生档位也不改变“最近一次独立做对”、权重学习往数据方向走且样本少时收缩、学生端没有数字。

收集哪些数据、每个数怎么算、学期里要做什么，见 [研究数据与指标](研究数据与指标.md)。

## 7. 局限

- 量规的四档是教学上的划分。盲评页已经有了，但还没有真实的老师评分；样本少于 100 个时 κ 的置信区间很宽。盲评的老师可能认得出学生的说话方式。
- 融合的权重学的是“预测下一题能不能一次做对”，这个目标本身偏向做题表现，理解、保持这类维度的价值可能被低估。
- 对话行为和成绩的相关是描述性的，不是因果。
- 演示数据是编的，演示数据上学到的权重没有意义。
- 跨课程联系的检验用的是学生现在的 C 语言估计，不是学数据结构那一刻的；C 语言课在前、数据结构课在后时影响不大。检验是相关，不是因果：C 学得好的学生可能整体都学得好。
- 跨课程联系是技能一层的，数据结构的题少时多数联系会停在“数据还不够”。
