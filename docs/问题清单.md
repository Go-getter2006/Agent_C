# 问题清单

写给张明诚。分四部分：需要你确认的、我自己做了取舍的、在开发环境里没法验证的、总说明第 11 节各项的现状。

总说明第 0 节原本要求先交方案和问题清单、确认后再写代码。按你后来的指示（自己规划、不用再问、真实后端一起做），我直接做了实现，这份清单和 [技术方案](技术方案.md) 随代码一起交。下面每一条都可以改，改动范围我尽量写清楚。

## 一、需要你确认的

### 掌握程度算法

1. **“还没练到”的门槛用哪个证据量。** 附件一 8.5 写的是 S+F<1。S、F 是带遗忘的，照字面做的话，一个只做过一道题的技能过几天证据量就掉到 1 以下，又变回“还没练到”。我改成用**不带遗忘**的证据量判断“练到没有”，带遗忘的只用来算 p。
2. **“自己改了几次后独立通过”只算 0.5。** 这样只做过这一道题的知识点，证据量不到 1，仍然显示“还没练到”。页面上的依据写成“做过 1 题，还不够判断”。这是照文档做的结果，看起来有点别扭，是否符合你的预期？
3. **遗忘会让早先一次通过的知识点掉回“待加强”。** 一次通过（S=1）之后约 35 天不练，p 降到 0.6 左右，再久就低于 0.6。演示数据里有这样的知识点。是否符合预期？
4. **一道题的证据记到哪些技能上。** 文档没有规定。2026-11-20 起：主技能全额；次技能里有测试点专门考它的按 0.6 算、照常算独立成功，只是顺带用到的按 0.2 算、不算独立成功（`config.MASTERY` 的 `secondary_tested_factor`、`secondary_incidental_factor`）。以前一律按 1.0，输出格式、读入这类几乎每道题都用到的技能每过一道题就涨。以前记下的证据后台按新规则重算（`mastery.reweigh_passes`）。这两个数是暂定值，学期末当参数估计。

### 对话

5. **规则表 R08 和例二不一致。** R08 写“升一级”，例二却从 H0 直接到了 H2。我的处理：反问时如果已经把出问题的行贴出来了（相当于做过 H1），下一级直接到 H2；否则 H0 → H1 → H2。
6. **规则表没有覆盖的情况。** 回合中途学生又问了一个调试问题（不是回答反问，也不是点按钮），R01~R11 都不匹配。我加了一条兜底，编号记为 R00：保持当前的帮助级别，不升级。点“我想自己想想”也记 R00。
7. **“直接讲给我”连点两次。** 第一次按 R10 给 H1 或 H2；已经到过这一级再点，就再升一级。只要升到 H3（要给代码），一律按 5.6 的卡点流程处理：第一次给示例并记卡点，第二次先让他回忆。
8. **回访题、回忆题怎么出。** 文档说“登录时出”。现在合并成了“复习”：卡住、需要示例代码、改正后又犯同样的错、小题答错的技能会加进复习，按间隔重复安排（见技术方案 5.5）。没有自动弹出来，而是在侧边栏“复习”上标一个数、题目列表上方有一条提醒、学情页“接下来做什么”里列出来，学生点了才出题。原因是自动往某个对话里插一道不相干的小题比较突兀。复习的参数（到期线 0.75、每天最多两道、连对三次算巩固）都在 `config.REVIEW`。
9. **代码本来是对的，学生却选“有错”。** 现在的做法：让他改并运行一次，然后告诉他“这段代码本来就是对的”，记下他改了哪几行。题库里判断型（JUDGE）的题没有这一步，直接判错。

### 同步

10. **题库改动多久查一次。** 题库是同一台服务器上所有老师共用的，按服务器同步，不按老师：一天拉一次题目列表（几个请求）；作业里用到的题每天核对测试点列表和题面，变了才重新下载；整个题库的测试点文件每 7 天全量核对一次（大约 5000 次请求，排在最低优先级里慢慢做）；另外每次取失败测试点的输出时会顺带核对，发现不一致立刻重抓这道题。想改成每天全量，把 `sync_meta.FULL_ASSET_CHECK_DAYS` 改成 1。

### 界面

11. **界面重做后和设计规范不一样的地方**（深色侧边栏展开、学生消息用气泡、卡片有很淡的阴影、教师端用指标卡等）都列在 [design/审查记录](design/审查记录.md) 第 3 节，逐条写了原因；规范明令禁止、改了也没带来好处的几处已经改回来了。哪条不同意请告诉我。学情页的顺序：顶部是一排做题事实，下面左边“接下来做什么”和知识点，右边每周提交、常见错误、作业进度。
12. **题目列表最下面多了一行“其他问题”**，用来问概念、题意，或者不确定是哪道题的问题，回访小题也出在这里。原型里没有这一行。
13. **提交页每一行多了“看代码”和“和上一次比”**；右栏最新一次提交下面多了“问问为什么错”。

### 内容

14. **技能表骨架（128 条）是我起草的**，在 `backend/app/taxonomy/skills.py`。文档里举的例子都原样收进去了，其余是按知识点表和错误类型库补的，需要任课老师过目。
15. **先修边初稿也是我列的**，在 `backend/app/taxonomy/prereq.py`，标着“初稿，未审定”：C 语言内部、数据结构内部，加 28 条从 C 语言到数据结构的跨课程边（合到知识点一级是 109 条边，其中 23 条跨课程）。用在 v2 的图先验、数据结构准备度、教师端的知识图谱和图模型里。
16. **小题现在按学生的情况出**（见技术方案 5.4），题库的 14 道只作最后的退路。附件一 6.3 说的“贴出他自己的代码，问把某行改成某样还对不对”已经做了。数据结构的技能还没有小题。
17. **数据结构的知识点表、技能表、错误类型是我起草的**（`taxonomy/ds.py`，30 个知识点、56 条技能），需要数据结构的任课老师过目。

### 掌握程度 v2 和复习

18. **“已掌握”的门槛已经放宽到 0.5**（大约三道题一次做对或很快改对）；改对了的失败按 0.2 算（`resolved_fail_factor`），待加强的线是 0.5（`weak_below`）。演示数据上档位从“已掌握 0、基本掌握 244、待加强 28”变成“17、249、6”。这几个数是暂定值，等真实数据多了看“模型对比”页再调。
19. **雷同的通过打几折。** 现在是 0.4（`copy_reliability`），判定条件是：和班里更早的通过规范化后一样、班里不到 30% 的人这样写、6 小时以内、代码不少于 40 个记号。这只是降低证据的分量，不对学生显示，也不算作弊认定；教师端学生列表和明细里能看到次数。
20. **教师总览“需要留意的学生”的规则**：同一知识点卡住三次以上、三个以上知识点待加强、一周没交题、还没交过题、某道题交了五次以上还没过、通过和同学雷同、一次通过率比全班低 30 个百分点以上、最近 7 天卡住两次。规则是透明的，不是预测模型。要增删哪条告诉我。

### 日志申请

21. **提问和回复的原文默认不给。** 要单独勾选，勾了也只给自己名下学生的。是否允许老师拿原文、拿了以后怎么用，可能需要学院的规定。
22. **下载链接 7 天失效、每人每天 20 次、一次最多 500 个学号、最长 366 天**，都在 `logs.py` 开头。

## 二、我做了取舍的地方

| 文档的写法 | 我的做法 | 原因 |
|---|---|---|
| 数据库只用 PostgreSQL | 正式环境用 PostgreSQL，同时支持 SQLite | 本机开发和测试不用先装数据库。同一套测试两种库都跑 |
| 表放在 `xdoj`、`sync` 两个 schema 里 | 用表名前缀 `xdoj_`、`sync_` | SQLite 没有 schema |
| 附件二 5.3 的视图 `submission_seq` | 没建视图，用查询算第几次提交 | 两种库写法不同，查询更简单 |
| 测试用 respx 模拟 HTTP | 写了一台假的 XDOJ（`xdoj/fake.py`） | 假服务器还能用来让演示数据走真实的同步流程 |
| 一个进程一个数据源 | 主循环管多个数据源，每分钟重新读一次数据源表 | 教师在网页上登记账号后不用重启 |
| 教师输入 XDOJ 地址 | 教师只能从管理员登记过的服务器里选 | 防止把账号密码发到随手填的地址 |
| 图模型的“先修边强度” | 只给了描述性统计（先修会与不会时后继“会”的比例） | 强度要等数据够了用 EM 估计，现在估出来没有意义 |
| 手机上改代码退成选择题 | 手机默认选择题，另有一个“我想自己改代码”可以切回去 | 有些学生手机上也愿意打字 |
| 代码块语法高亮 | 引用的代码不上色；小题的可编辑区只用加粗和一种灰蓝色 | 设计规范 4.6 |
| 等宽字体 JetBrains Mono 自托管 | 代码用 Maple Mono，西文用 Atkinson Hyperlegible Next，标题用得意黑，都跟着前端打包（都是 SIL OFL 1.1，许可在 `frontend/FONT-LICENSES.txt`）；中文正文仍用系统字体 | 按反馈换成 AI 生成的页面不常用的字体；整套中文正文字体太大，不值得 |

还有几处小的：

- 源码的编码检测先试 UTF-8，再试 GB18030，最后才用通用检测。通用检测会把 GBK 的中文注释认成别的编码。
- 学生贴的代码在后端识别（三个反引号围起来的，或连续几行像 C 代码的）。
- 按你的意见，大模型写回复时能看到题面、全部测试点和没通过的那几组的输入、期望输出、他程序的输出（完整，不截断；没取到的是 null，不当成空输出），用来判断错在哪、怎么引导；提示词要求绝不原样说给学生，回复校验也会拦截（出现了就重写，两次不行退回模板）。学生自己在页面上仍然看不到测试数据。
- 没配大模型时，概念提问只能回答内置的 9 条常见说明，其余会如实说“讲不了”。
- 固定模板只给二十来种常见错误写了专门的话，其余用通用模板。

## 三、在开发环境里没法验证的

1. **没有连过真实的 XDOJ。** 我没有账号。连接器是照《同步程序开发说明》第 4 节写的，文档没有逐一列出的字段是按候选名依次尝试的（例如提交列表里的结果字段试 `judgementStr`、`resultStr`、`result` 等；作业自带的 `classes[]`、`problems[]`）。评测结果是按文字里的关键词归到固定编码的，认不出的原样保存并写告警。第一次连真实服务器请按 [怎么验证](怎么验证.md) 第 2 节做，先跑 `xdoj-probe` 把字段名对一遍。附件二第 10 节的验收标准 1、2、4、5、6、7 都要在真实环境里做。
2. **没有 DeepSeek 的 key。** 大模型这条路只用假的后端测过：输出校验、重试、不合格时退回模板、不带学号姓名。提示词的实际效果没有看过。
3. **Docker 在开发环境里起不来。** `Dockerfile` 和 `docker-compose.yml` 没有实际启动过。沙箱的套接字服务和限制（限时、限内存、断网、不能写文件、不能再建进程）在本机直接跑的方式下测过。
4. **设计流程里指定的工具这里都没有**：inspo、awwwards MCP、agent-browser、cook 技能。参考网站在这个环境里打不开（网络代理拒绝），只看了搜索摘要和你发的四张图；多设备检查用 Playwright 截图；没有做 cook 评判。见 [design/references](design/references.md) 和 [design/审查记录](design/审查记录.md)。
6. **库道（DBEDU）的日志接口页面打不开**，日志申请是按你在消息里的描述做的。
5. **题库的规模口径**（477 还是 553）没法核对。

## 五、其他提醒

- **2026-11-26，多教师提交轮询相互阻塞已修复。** 同一服务器的提交游标原本按教师分别保存，但查询时间按服务器共用，第一位教师反复更新时间，后面的教师可能只有名单、没有提交。现在查询时间、成功时间和失败计数按数据源保存，提交分页轮流执行。题库仍按服务器共用，请求仍串行并经过原有限速器。更新并重启服务后会从各数据源已有游标继续补齐，无需删除数据或重新登记教师。回归测试覆盖第二位教师的旧提交、班级提交接口、重启后的查询间隔、分页轮转和错误退避隔离。未在真实虚拟机上确认补齐结果。
- **同日，详情下载与分析调度改进。** 共用队列中的提交详情、待评测跟进和回读，优先按提交班级关联选择教师会话，班号缺失时沿学生名单确认，避免用其他教师的账号请求。已取齐提交的分析先于普通历史详情执行，题库批量标注仍在普通详情之后。回归测试验证正确账号取齐详情且没有重试，以及普通详情积压时分析仍能执行。没有缩短请求限速间隔，没有新增重复评估，尚未实测生产环境耗时。

- **仓库是公开的。** 我没有把你给的五份原始文档和任何账号放进仓库，账号只写在 `.env` 里，`.env` 已经在 `.gitignore` 中。C 语言 XDOJ 的地址按你的指示写进了 `backend/app/servers.py`（出处是《总说明》3.1）；数据结构的服务器地址不同、还没给出，那一项是空的，别的课程用 C 语言的地址会被拒绝。
- **教师的 XDOJ 密码加密保存**，密钥从 `SECRET_KEY` 派生。换了 `SECRET_KEY`，已保存的密码就解不开，教师需要重新登录一次。
- **开发环境的沙箱不隔离读文件。** `SANDBOX_MODE=local` 只限时、限内存、断网、不让写文件。正式环境请用 compose 里的沙箱容器。
- **旧的研究原型已经删掉**，需要的话在 git 历史里（提交 `a6a7ff6`）。
