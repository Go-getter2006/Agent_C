# 首页与 UI 细节复查：五个 MCP 的实际参考

复查日期：2026-11-18。

本次先分别调用五个设计 MCP，再查看本机 Agent_C 的登录、聊天、学情、教师首页和知识图谱。结论是：优先重排首页的信息层级，减轻聊天的重复信息，再统一控件与文字密度。

本次只形成设计方案，未修改业务页面、接口或模型流程，未连接虚拟机和真实 XDOJ。界面使用本机 frontend/dist 和已打码的合成演示数据，由 Windows Edge 在 1440×1000、390×844 两种视口重新渲染；不能据此证明虚拟机当前部署版本、真实同步或模型调用的情况。

## 2. 对照当前页面，真正值得改的地方

### 2.1 首页的内容顺序比装饰更影响体验

教师首页当前先呈现五项统计，再呈现两张大趋势图，然后才是需要留意的学生。在本机合成数据下：

| 内容 | 1440px 桌面视口的位置 | 390px 手机视口的位置 | 设计判断 |
| --- | --- | --- | --- |
| 教师首页“需要留意的学生”标题 | 页面 y≈607px | y≈1242px | 主要教学行动被放在统计和趋势之后，手机首屏看不到 |
| 教师首页“作业完成情况”标题 | y≈2507px | y≈3652px | 被较长的知识点分布推得很靠后 |
| 学生学情“接下来做什么”标题 | y≈256px | y≈385px | 已有明确行动入口，值得复用到学生首页 |
| 学生学情“作业进度”标题 | y≈1035px | y≈4825px | 手机按左列完整内容再排右列，长知识点列表把作业信息推到后面 |

这些是该演示数据与该视口的测量，不是所有班级的固定位置。它们揭示的是排序问题：重要内容不应依赖上方列表有多长。

### 2.2 学生目前没有独立的学习首页

当前 App 路由让学生默认进入 /chat，打开后就是题目列表、对话和右侧资料的工作台。已有学情页中的“接下来做什么”其实更接近学生进入系统时需要的起点。

建议提供一个轻量学习起始区：上次的题目、未完成的问题、当前作业、到期复习。已有题目链接仍然直接进入对话，不增加中间跳转；学生继续原有对话时也不必反复经过欢迎页。

### 2.3 聊天区重复展示同一份状态

桌面截图中，左侧题目项、中央标题栏、右侧“这道题的提交”都能看到评测状态、提交次数或测试组通过情况。与此同时，右侧还展开多次提交的差异。

建议明确分工：左侧负责选题，中央负责当前问题和对话，右侧按需查看题目与提交证据。保留完整提交记录页的检索和代码对比价值，减少当前工作台中历史记录的默认展开量。

### 2.4 中文字体已经正常回退，重点是字号和密度

通过 Chrome DevTools Protocol 的 CSS.getPlatformFontsForNode 核对，本机可见中文标题和聊天正文实际使用 Microsoft YaHei UI，英文使用 Inter。没有发现本次 Windows 渲染发生宋体回退。

部分辅助内容为 12–13px，多处并列显示长说明、状态、错误标签和代码差异，视觉负担主要来自信息密度。可以将长文本的常规阅读字号提高到 15–16px，标签和辅助说明保持 12–13px；代码继续使用独立等宽字体。Linux 字体回退仍需在实际部署环境另验。

### 2.5 手机上存在控件尺寸不一致

本次测量的例子：

- 登录主按钮高 42px，手机仍是 42px。
- 手机聊天的三个引导选项高 40px。
- 显示密码按钮可点击区域约 36×32px。
- 多数手机输入框、选择框已达到 44px。

这是统一触控体验的机会，不把它表述成全部按钮不合规。建议手机常用触控区域统一至少 44px，图标可保持较小；桌面常规按钮 40px，紧凑工具栏按用途保留更小规格。

### 2.6 图谱已经具备基础交互，首屏组织还可改进

当前已有搜索、章节选择、缩放、节点详情、图表切换和稳定布局，没必要重复开发这些功能。问题是总览节点偏小；手机筛选、说明和图例占据首屏大半，下方才开始显示图。

应先改善“概览—章节—局部路径”的阅读方式，让用户先找到目标，再读其先修和后续关系。五个灵感工具这次没有返回足以代表专业知识图谱的直接案例，不能把宣传页截图当作图谱专业依据。

## 3. 两个方向的取舍

| 方向 | 参考依据 | 适用位置 | 取舍 |
| --- | --- | --- | --- |
| 学习任务优先 | Brightpath 的课程/进度归组、Brilliant 的明确学习入口 | 登录后的学生首页、教师首页、日常聊天 | 推荐作为主体。页面先说明当前任务和下一步，再展示分析 |
| 编辑式视觉表达 | Design Education Series 的分栏和字级、Noah Stokes 的留白、Spek 的产品画面 | 登录页的介绍区、空状态或产品介绍 | 局部采用。高频学习界面仍需要较高的信息效率，不能把宣传页比例整页照搬 |

统一方向是“清晰的编程学习工作台”。保留花括号与黄色标识，以真实代码片段、题目状态和学习路径形成识别性；避免另造一套与业务无关的插画和渐变。

## 4. 首页具体怎么排

### 4.1 学生：首页先回答“我接下来做什么”

参考 Brightpath 的课程进度归组与 Brilliant 的明确行动入口，建议：

```text
侧边导航 │ C 语言程序设计                       当前作业
         │
         │ 继续上次的问题
         │ 成绩最高分
         │ 第 3 次提交，仍有 1 组未通过
         │ [继续分析这次提交]              [查看题目]
         │
         │ 当前作业                         到期复习
         │ 作业名称、截止日期、已完成/总题数  主题、到期状态
         │ 未完成题目的简短列表              [开始复习]
         │
         │ 最近对话 / 最近练习
```

以上题名和次数只用于方案示意，不是新增真实学生记录。正式页面由现有数据决定；没有上次题目时，主区域改为“从当前作业选择一道题”。

细节：

- 主要动作突出“继续分析这次提交”，题目详情采用次级按钮。
- 当前作业与复习的排序服从实际状态：到期复习可前移，无到期内容时不展示空的提醒卡。
- 首屏不再放整张知识点卡片墙；学情页仍承载详细分析。
- 作业进度同时写出“已完成/总题数”，不能只靠绿色进度条表达。
- 题目未提交、资料正在获取、获取失败分别处理。失败后自动重试；持续失败给出可理解的说明，不长期显示“稍等几秒”。
- 刚进入系统的新学生得到选题入口；有明确题目上下文的访问直接进入工作台。

### 4.2 教师：首页先回答“我需要关注谁、为什么”

参考 Brightpath 的信息分区，结合本项目的教学用途重新排序：

```text
班级总览                                 [当前班级]
本周概况：做过题的人数 / 提交 / 复习，压缩为一行
────────────────────────────────────────────────
需要关注的学生                     共性问题
学生、具体证据、最近变化             常见问题、涉及人数
[查看学生详情]                     [查看相关记录]
────────────────────────────────────────────────
当前作业完成情况                   近期趋势（紧凑图）
────────────────────────────────────────────────
知识点分布摘要                     [查看完整知识图谱]
```

细节：

- 不让五张等权统计卡占据最醒目的整排；三项核心指标或一行摘要就够。
- 原本的大趋势图后移，默认给出最近几周，完整趋势保留查看入口。
- 学生列表中同时显示原因与证据，如相关知识点、最近作答或未解决问题；仅有模型估计时明确说明。
- “提交数下降”默认中性色呈现。提交少可能来自课表、作业量或完成情况，不能仅凭下降就用红色暗示学情变差。
- 首页的知识点分布展示摘要和异常重点，完整长表留给详情。
- 手机优先呈现关注学生和当前作业，统计、趋势随后，不直接将桌面左列排完再排右列。
- 不从参考站移植本系统没有的“发提醒”“新建作业”等功能按钮。

### 4.3 登录页：把产品价值讲清楚，并让表单更集中

参考 Spek、Interfere 的产品界面展示，以及 Awwwards 返回页面的视觉重心：

- 保留桌面左右分区。左侧减少三段同等重量的说明，使用一条主句、简短介绍和一段真实工作台样式的演示。
- 主句可用“从一次错误提交，找到下一步怎么改”；配一段代码和引导提问，直接说明产品在做什么。
- 调整“交了题马上能看到结果”为“自动整理 XDOJ 的练习提交”，避免作出即时同步承诺。
- 表单保持约 380–420px 的容器，身份切换、课程选择、输入框和主按钮使用同一间距规则。
- 登录按钮按身份显示“进入学习”或“进入教师工作台”，加载时保持宽度，避免界面跳动。
- 已有显示密码和错误提示继续保留，扩大图标触控区域。
- 手机隐藏大段介绍，只保留名称、简短用途、身份和表单。演示环境提示应写给使用者，环境变量名称放在管理员说明中。
- 不添加没有后端能力的注册、找回密码或第三方登录按钮。教师后台同步需要保存加密凭证，不能笼统宣称所有密码都不保存。

## 5. 统一 UI 细节的具体规格

Brightpath 的 DESIGN.md 返回了正文 16px、控件 40px、按钮圆角 8px、4px 间距单位。以下是针对本项目的适配建议，并非来自 A1 的实测参数：

| 对象 | 建议 | 目的 |
| --- | --- | --- |
| 颜色角色 | 延续石墨黑导航、灰白内容、黄色品牌标识；蓝色用于链接和焦点；红绿用于结果 | 让品牌、操作、业务状态各司其职 |
| 主按钮 | 高 40px；手机触控区域至少 44px；圆角 8px；每个主要区域一个主动作 | 减少黑色按钮之间的竞争 |
| 次按钮与工具按钮 | 详情、查看题目用描边或文字按钮；折叠、复制用有名称的图标按钮 | 区分行动优先级 |
| 字体 | 标题 24–30px，区块标题 16–18px，阅读正文 15–16px，辅助信息 12–13px | 增强字级，不简单将所有文字一起放大 |
| 间距 | 4px 为基础；同组 8–12px；模块内 16–24px；模块间 24–32px | 让关系通过距离体现 |
| 数字 | 同类统计统一格式；时间弱化；数值与单位分开字级；表格数字对齐 | 提高比较效率 |
| 边框和阴影 | 密集工作台以浅边框分区；弹层再使用明显阴影 | 减少卡片套卡片 |
| 评测状态 | 图标加文字；测试组方块保留可读说明 | 不只依赖红绿颜色 |
| 空状态 | “没有练习”“没有证据”“正在获取”“获取失败”使用不同文案和表现 | 避免错误理解 |
| 焦点和加载 | 保留已有焦点；加载占位稳定；后台刷新不把用户滚回顶部 | 减少操作中断 |

不要直接沿用示例里的所有字号、紫色辅助色或很小的标签。中文密度、真实业务和可访问性优先于参考设计。

## 6. 聊天和知识图谱的配套调整

### 聊天

- 中央围绕当前提交展开。标题保留题名、当前结果和次数；长题目摘要不挤占同一行。
- 左侧列表只留用于选题的关键信息，减少重复的测试组方块。
- 右侧以“题目 / 本次提交 / 相关知识”组织，历史提交默认折叠；需要代码对比时再展开。
- 约 1440px 及以上可以保留资料栏；窄桌面改为可打开的侧栏，不继续挤压对话阅读区。
- “继续想想 / 给点提示 / 详细解释”作为同一组引导动作，手机允许整齐换行，扩大可点击区域。
- 隐藏测试点输入输出仍只供模型内部分析，学生界面不因重设计而开放这些内容。
- 完整提交记录栏目仍有历史浏览、筛选和版本对比价值；首页与聊天只展示当前相关摘要。

### 知识图谱

- 首层展示章节和概念组，第二层看当前章节，第三层看某个节点及直接关系；完整课程图保留。
- 手机压缩图例并可展开，章节和搜索优先；局部路径优先于整张图缩到无法阅读。
- 选中节点后保持位置不变，突出先修与后续；详情按“概念—证据—相关题目—下一步”组织。
- 本次未取得专业图谱产品的直接设计证据，以上是结合现有稳定有向布局提出的产品建议，后续图谱专项需另补直接案例。
- 不改变边的含义、模型档位或跨课程权限，不将无练习等同于掌握差。

## 7. 推荐先做的三批改动

1. 首页排序：教师关注列表与作业前移；学生提供继续学习起始区；手机按任务重要性重排。
2. 精修核心流程：统一按钮规格和触控区域、阅读字级、登录说明；聊天资料去重，区分获取中与失败。
3. 图谱阅读：章节概览、局部路径、手机工具区和详情组织，再考虑更细的视觉和动画。

验收时用长题名、多次提交、空班级和慢网络检查桌面与手机。当前本机十个页面/视口组合未出现 JS 页面错误，也没有缺失的合成 API 路由；手机学情页仍有 1px 根节点宽度差异，没有证据将其认定为严重横向裁切。

本机截图与测量记录位于工作区 outputs/design-review/，不随仓库发布。

本报告完成后仍未改动正式 UI。后续落地应先形成首页和聊天的桌面/手机样稿，再按本项目现有 React、TypeScript、CSS 和业务接口实现。
